# 受限事件命题模型

面向个人情报分析的自然、可计算事件表达

## 1. 摘要

情报文本并不只陈述“发生了什么”。它还会陈述某件事正在计划、已经获批、可能发生、尚未完成、被某方否认，或者与另一件事存在因果关系。如果把这些内容全部压缩为一个事件类型和一个阶段字段，就会混淆三个不同层次的问题：

1. **事件是什么**，例如收购、撤退、停产或价格上涨；
2. **如何限定这个事件**，例如计划收购、获准收购、正在收购或否认已经收购；
3. **事件之间有什么关系**，例如短缺导致停产、增援阻止失守。

本设计据此提出“受限事件命题模型”（Controlled Event Proposition Model，CEPM）。模型以一条情报为边界，将其中值得保留的内容表达为一个小型命题图。图中只有三类语义对象：

- **事件核（Event）**：描述现实或设想中的状态、过程与变化；
- **事件限定（Qualification）**：对事件或命题施加阶段、意向、许可、认知、否定等限定；
- **事件关系（Relation）**：连接两个事件或命题，表达因果、时序、条件等关系。

事件谓词允许扩展；FRAME 维度、限定算子和关系谓词保持小型、封闭和稳定。模型允许有限组合，但不允许任意递归。由此可以同时获得自然表达能力、计算稳定性和适合个人维护的规模。

## 2. 设计目标

### 2.1 目标

- 从一条情报中提炼一项或少量核心事件及其决定性信息；
- 区分事件本身、对事件的限定以及事件之间的关系；
- 在谓词表不可能完整进入提示词的条件下保持基本结构稳定；
- 允许长尾事件先以未归一化形式存在，不因词表缺失而丢失整条记录；
- 支持稳定检索、粗粒度统计、精确谓词分析和自然文本生成；
- 让底层结构可以被机器处理，让上层展示仍接近分析人员的自然表达；
- 控制结构复杂度，使个人能够理解、检查和维护。

### 2.2 非目标

- 不试图预先建立覆盖现实世界的完整事件本体；
- 不把一篇文章中的每个句子都转换为逻辑形式；
- 不把语言理解简化为完全形式化的定理证明；
- 不在本模型中解决跨情报实体消歧和跨来源事实融合；
- 不因能够表达复杂嵌套，就保留所有修辞、转述和认知层次。

## 3. 基本假设

### 3.1 情报是记录边界

每个事件描述只属于产生它的那条情报。一条情报可以包含多个事件描述，这些描述可以互相引用；不同情报中的相似事件是否指向同一现实事件，属于后续分析任务，不是本模型的存储前提。

因此，本设计不引入独立的 Observation 对象。来源、标题、发布时间和全文位置由情报记录统一承载；命题只需要保留其在该情报中的局部依据。

### 3.2 结构化不等于穷尽

模型只保存会改变核心判断的信息。删除某项信息后，如果读者会误判事件是否存在、是否已经执行、能否继续、涉及谁、规模多大或为何发生，该信息通常应进入结构；一般背景和重复修辞不进入核心命题。

### 3.3 被提及不等于被断言

“公司计划收购工厂”提及了收购事件，但没有断言收购已经发生。“国防部否认部队已经撤退”提及了撤退及其完成状态，但文章实际断言的是一次否认。

因此，模型必须区分：

- **命题节点**：为了表达内容而建立的事件或限定；
- **根断言**：该条情报实际主张成立的命题；
- **焦点事件**：分析人员希望持续关注的底层事件。

只有进入根断言的命题才由该情报直接主张。被其他命题引用的事件核不会自动获得事实地位。

## 4. 理论基础

本模型不是对某一种语言学理论的完整实现，而是吸收几项成熟思想形成的工程化子集。

### 4.1 事件语义

Davidson 式事件语义把动作句理解为存在一个事件变量，并把参与者、时间、地点等信息作为对该事件的约束。例如“公司A收购公司B”可以理解为存在一个收购事件 $e$：

$$
Acquire(e) \land Acquirer(e, A) \land Asset(e, B)
$$

这种表达允许时间、地点、金额和方式分别附着于同一个事件，不必把所有组合都制造成新的谓词。

### 4.2 角色语义与 FRAME

Fillmore 的框架语义和后续语义角色研究表明，谓词会唤起一种参与者结构。例如“收购”通常涉及收购方、标的和可能的出售方；“撤退”通常涉及撤退主体、起点和目的地。

FRAME 在本模型中不是现实事件的唯一类别，而是事件核的**结构轮廓**。它提供跨谓词的粗粒度比较和候选检索，具体角色约束仍由谓词注册项定义。

### 4.3 体、模态与命题作用域

“正在”“已经完成”描述事件展开方式；“计划”“允许”“必须”描述事件与意向、权限或义务的关系；“认为”“否认”“预计”描述主体对一个命题的认知立场。它们并不是与“收购”“撤退”同层的事件身份。

命题作用域解释了以下两句话为何不同：

```text
否认(完成(撤退))
完成(否认(撤退))
```

自然语言允许复杂嵌套，但情报提炼只需要保留会改变判断的有限作用域。

### 4.4 事件关系

因果和时序不是单个事件内部的角色，而是两个事件或命题之间的关系。例如“短缺导致停产”包含短缺事件、停产事件和连接两者的因果关系。把整句话注册为“短缺导致停产”谓词，会造成不可控制的组合增长。

## 5. 总体模型

一条情报被表达为一个局部命题包：

$$
I = (M, N, A, F)
$$

其中：

- $M$ 是情报元数据；
- $N$ 是事件、限定和关系节点的集合；
- $A$ 是该情报的根断言集合；
- $F$ 是一个或少量焦点事件。

形式语法为：

$$
P ::= E \mid Q(P) \mid R(P, P)
$$

- $E$ 表示事件核；
- $Q$ 表示事件限定；
- $R$ 表示事件关系；
- $P$ 表示任意命题节点。

工程实现使用带引用的有向无环图，而不是无限嵌套的文本树。节点拥有情报内局部 ID，其他节点通过 ID 引用它。

## 6. 三类语义对象

### 6.1 事件核 Event

事件核回答：**所关注的状态、过程或变化究竟是什么？**

事件核包括：

- 可扩展但可治理的事件谓词；
- 多维 FRAME；
- 谓词定义的具名角色；
- 直接属于事件的时间、地点、数量和方式等修饰信息。

示例：

```yaml
id: E1
kind: event
predicate:
  canonical: 收购
  surface: 拿下
  status: mapped
frame:
  dynamics: change
  topology: transfer
  agency: agentive
arguments:
  acquirer: 公司A
  asset: 公司B控股权
modifiers:
  amount:
    value: 20
    unit: 亿元
    currency: CNY
  expected_end:
    normalized: 2026-12-31
    precision: year
    surface: 2026年底
```

事件核可以表示实际事件，也可以只是另一个命题所引用的设想内容。它是否被该情报断言为事实，由根断言和外层限定决定。

### 6.2 事件限定 Qualification

事件限定回答：**这条情报以什么方式看待或约束该事件？**

限定具有作用域，它可以指向一个事件，也可以指向已经限定过的命题。常见限定包括：

- 事件展开到什么阶段；
- 主体是否形成意向或计划；
- 某行为是否获得许可、受到命令或被禁止；
- 某主体认为、预计、怀疑或否认什么；
- 命题是否带有明确否定、可能性或条件。

示例：

```yaml
id: Q1
kind: qualification
family: intention
value: planned
holder: 公司A
target: E1
```

```yaml
id: Q2
kind: qualification
family: authorization
value: pending
authority: 监管机构
target: E1
```

这两个限定可以同时成立。它们不再被压缩成一个互斥的 `stage`。

### 6.3 事件关系 Relation

事件关系回答：**两个事件或命题之间存在什么联系？**

关系节点至少引用两个命题。常见关系包括：

- 因果：导致、促进、阻止、加剧、缓解；
- 时序：先于、后于、同时、重叠；
- 条件：以某命题成立为条件；
- 结构：组成、替代、依赖。

示例：

```yaml
id: R1
kind: relation
family: causal
predicate: 导致
arguments:
  cause: E2
  effect: E3
```

关系自身也是一个命题，因此可以成为根断言，也可以受到限定。例如“分析师认为短缺将导致停产”可表示为 `认为(R1)`，而不是把“认为短缺导致停产”制造为一个新谓词。

## 7. FRAME：从单选类别变为结构维度

### 7.1 FRAME 的职责

FRAME 只描述事件核的粗粒度结构，不承担以下职责：

- 不标识具体事件身份；
- 不表达计划、批准、否认和可信度；
- 不表达两个事件之间的因果关系；
- 不决定该事件是否被情报断言为事实。

FRAME 的价值在于：即使具体谓词尚未归一化，系统仍然知道事件大致是状态、过程还是变化，以及参与者如何组织。

### 7.2 动态形态 dynamics

| 值      | 含义                             | 示例                   |
| ------- | -------------------------------- | ---------------------- |
| state   | 某种状态或关系在时间范围内成立   | 位于、拥有、控制、依赖 |
| process | 活动正在展开，不以状态跳变为核心 | 生产、巡逻、谈判、研发 |
| change  | 对象在某个维度上由前态转向后态   | 上涨、停产、任命、收购 |

这一区分吸收了事件体研究中状态、活动和变化的基本差异，但不要求完整复刻语言学中的所有体类别。

### 7.3 参与拓扑 topology

| 值         | 含义                             | 典型结构                       |
| ---------- | -------------------------------- | ------------------------------ |
| intrinsic  | 主要描述一个主体自身的状态或变化 | subject、dimension、value      |
| relational | 描述两个或多个参与者间的稳定关系 | subject、counterpart、relation |
| targeted   | 行动或作用明确指向目标           | actor、target、instrument      |
| transfer   | 某个对象、权利或位置在端点间转移 | theme、source、destination     |

### 7.4 施动性 agency

| 值           | 含义                               |
| ------------ | ---------------------------------- |
| agentive     | 存在主动发起或控制事件过程的主体   |
| non_agentive | 事件表现为自发变化或无意志主体过程 |
| unknown      | 材料不足以判断                     |

施动性是辅助维度。它可以帮助区分“公司提高价格”和“价格自然上涨”，但不替代具体谓词角色。

### 7.5 常见组合

| 事件             | dynamics | topology   | agency       |
| ---------------- | -------- | ---------- | ------------ |
| 公司拥有工厂     | state    | relational | non_agentive |
| 工厂持续生产芯片 | process  | targeted   | agentive     |
| 铜价上涨         | change   | intrinsic  | non_agentive |
| 部队攻击阵地     | process  | targeted   | agentive     |
| 公司收购业务     | change   | transfer   | agentive     |
| 部队撤退至后方   | change   | transfer   | agentive     |

FRAME 是维度向量，而不是要求每个事件只能进入一个箱子。同一组合可以覆盖大量谓词，具体差异由谓词和角色表达。

## 8. 谓词与角色

### 8.1 三种词汇策略

三类对象采用不同的开放程度：

| 对象              | 词汇策略     | 原因                         |
| ----------------- | ------------ | ---------------------------- |
| 事件谓词          | 外置、可扩展 | 现实事件类型存在大量领域长尾 |
| 限定 family/value | 小型封闭集合 | 需要稳定表达作用域与事实状态 |
| 关系谓词          | 小型封闭集合 | 关系数量有限，需支持一致推理 |

因此，模型不是“所有谓词固定”，也不是“所有谓词自由生成”。它对不同语义层采用不同治理策略。

### 8.2 事件谓词注册项

事件谓词注册表不需要完整进入提示词。每个注册项至少包含：

```yaml
id: transaction.acquire
label: 收购
aliases:
  - 并购
  - 买下
  - 取得控制权
frame:
  dynamics: change
  topology: transfer
  agency: agentive
roles:
  required:
    - acquirer
    - asset
  optional:
    - seller
modifiers:
  - amount
  - effective_time
  - expected_end
```

稳定 ID 用于计算，标准标签用于展示，别名用于检索和映射，原文表达用于审计。

### 8.3 未归一化谓词

找不到合适注册项时，不允许模型现场创建正式谓词。记录使用 `unresolved`：

```yaml
predicate:
  canonical: null
  surface: 接管其欧洲订单
  status: unresolved
  gloss: 将订单承接关系转移给新的供应商
frame:
  dynamics: change
  topology: transfer
  agency: agentive
```

该记录仍可参与 FRAME、实体、时间和地点层面的分析，但不能参加某一精确谓词的统计。后续可以人工映射到已有谓词、增加别名，或注册确有必要的新谓词。

### 8.4 角色约束

角色由具体谓词定义，FRAME 只提供回退角色。这样既能保持“收购方”“标的”等自然语义，也能在谓词未知时退回 `theme/source/destination` 等通用结构。

同一事实不得同时使用谓词角色和 FRAME 回退角色重复保存。例如已使用 `acquirer` 后，不再额外保存意义相同的 `destination`。

## 9. 事件限定体系

限定采用封闭的 family 和 value。第一版建议只保留对情报判断有直接价值的集合。

### 9.1 生命周期 aspect

| value       | 含义                     |
| ----------- | ------------------------ |
| not_started | 明确尚未开始             |
| ongoing     | 已经开始且仍在进行       |
| suspended   | 已开始但暂时中止         |
| completed   | 达到目标或完成标准       |
| terminated  | 在完成前被主动终止       |
| failed      | 已实施或尝试但未达到目标 |

### 9.2 意向 intention

| value       | 含义                   |
| ----------- | ---------------------- |
| considering | 正在评估，尚未形成计划 |
| planned     | 已形成计划或方案       |
| committed   | 已作出明确承诺         |

### 9.3 授权 authorization

| value    | 含义                     |
| -------- | ------------------------ |
| required | 明确需要授权，但状态未知 |
| pending  | 正在等待授权决定         |
| approved | 已获得授权               |
| rejected | 授权被拒绝               |
| revoked  | 已有授权被撤销           |

### 9.4 指令 directive

| value      | 含义               |
| ---------- | ------------------ |
| requested  | 被请求实施         |
| ordered    | 被有权主体命令实施 |
| required   | 负有实施义务       |
| prohibited | 被禁止实施         |

### 9.5 认知立场 epistemic

| value     | 含义                 |
| --------- | -------------------- |
| believed  | 主体认为命题成立     |
| estimated | 主体作出估计或预测   |
| doubted   | 主体怀疑命题成立     |
| denied    | 主体明确否认命题成立 |

### 9.6 可能性 modality

| value       | 含义                         |
| ----------- | ---------------------------- |
| possible    | 有发生可能，但未判断为更可能 |
| probable    | 被判断为较可能发生           |
| conditional | 仅在明确条件成立时发生       |

情报来源本身的可信度不放入 epistemic。`epistemic` 描述文章中的主体态度；来源可靠性是情报元数据或后续评价。

## 10. 事件关系体系

第一版关系表应保持小而稳定：

| family      | predicate | 含义                             |
| ----------- | --------- | -------------------------------- |
| causal      | 导致      | 原因使结果发生或形成             |
| causal      | 促进      | 原因提高结果发生概率、速度或程度 |
| causal      | 阻止      | 原因使结果未发生或无法继续       |
| causal      | 加剧      | 原因提高既有负面状态的程度       |
| causal      | 缓解      | 原因降低既有负面状态的程度       |
| temporal    | 先于      | 第一命题在第二命题之前发生       |
| temporal    | 后于      | 第一命题在第二命题之后发生       |
| temporal    | 同时      | 两个命题在相关时间范围内同时成立 |
| conditional | 条件      | 第一命题成立是第二命题成立的条件 |
| structural  | 组成      | 第一事件是第二事件的组成部分     |
| structural  | 替代      | 第一事件或对象取代第二事件或对象 |
| structural  | 依赖      | 第一事件的实现依赖第二命题成立   |

“迫使”同时包含强因果和主体行动色彩。第一版宜表达为“导致 + directive/非自愿”等可解释组合，而不是不断增加边界模糊的关系谓词。

## 11. 事实地位与作用域

### 11.1 根断言

命题包必须列出根断言：

```yaml
assertions:
  - Q1
  - Q2
focus:
  - E1
```

如果 `Q1 = 计划(E1)`，则情报断言“计划”成立，而不是断言 `E1` 已发生。如果 `Q2 = 待批准(E1)`，则情报断言存在这个审批门槛。

### 11.2 焦点事件

焦点事件用于回答“这条情报主要在跟踪什么”。焦点不等于根断言：

- “公司计划收购业务”的根断言是计划，焦点是收购；
- “监管机构批准收购”的根断言是批准，焦点仍可以是收购；
- 如果分析目标就是监管行为，批准本身也可以被建模为事件核并成为焦点。

焦点允许展示和检索围绕稳定事件身份展开，而根断言保证不把计划内容误当成既成事实。

### 11.3 有限嵌套

模型允许必要的限定嵌套：

```text
否认(完成(撤退(...)))
预计(可能(上涨(...)))
```

第一版最多允许两层限定。更深结构通常不值得进入核心表达，应拆成多个命题或保留为自然语言备注。

关系两端可以是事件核或限定后的命题，但命题图不得形成循环引用。

## 12. 时间、地点与数量

时间、地点和数量不是新的语义对象，而是事件或限定的修饰信息。它们附着于实际拥有该信息的节点。

例如：

- 收购预计完成时间附着于收购事件；
- 监管机构批准时间附着于批准限定；
- 分析师作出预测的时间附着于预测限定；
- 撤退起点和终点属于撤退角色，不是普通发生地点。

时间值应同时保留：

```yaml
normalized: 2026-12-31
surface: 2026年底
precision: year
timezone: null
```

数值应拆分数值、单位和币种，不能只保存展示字符串。无法可靠标准化时保留 `surface`，并将标准化值留空。

缺失状态统一为：

- 字段不存在：原文没有提供且该字段不是必要字段；
- `unknown`：原文明示存在该值，但当前材料无法确定；
- `not_applicable`：该字段对当前谓词不适用。

## 13. 完整示例

### 13.1 计划收购且等待审批

原文：

> 公司A计划以20亿元收购公司B控股权，交易仍需监管机构批准，预计于2026年底完成。

结构：

```yaml
events:
  - id: E1
    kind: event
    predicate:
      canonical: 收购
      surface: 收购
      status: mapped
    frame:
      dynamics: change
      topology: transfer
      agency: agentive
    arguments:
      acquirer: 公司A
      asset: 公司B控股权
    modifiers:
      amount:
        value: 20
        unit: 亿元
        currency: CNY
      expected_end:
        normalized: 2026-12-31
        precision: year
        surface: 2026年底

qualifications:
  - id: Q1
    kind: qualification
    family: intention
    value: planned
    holder: 公司A
    target: E1

  - id: Q2
    kind: qualification
    family: authorization
    value: pending
    authority: 监管机构
    target: E1

assertions: [Q1, Q2]
focus: [E1]
```

标准文本：

> 公司A计划以20亿元收购公司B控股权，交易尚待监管机构批准，预计于2026年底完成。

### 13.2 命令撤退

原文：

> 指挥部命令第X旅在24小时内从A地区撤退至B地区。

```yaml
events:
  - id: E1
    kind: event
    predicate:
      canonical: 撤退
      surface: 撤退
      status: mapped
    frame:
      dynamics: change
      topology: transfer
      agency: agentive
    arguments:
      unit: 第X旅
      source: A地区
      destination: B地区
    modifiers:
      deadline:
        value: 24
        unit: 小时

qualifications:
  - id: Q1
    kind: qualification
    family: directive
    value: ordered
    controller: 指挥部
    subject: 第X旅
    target: E1

assertions: [Q1]
focus: [E1]
```

这里没有断言撤退已经开始。后续同一条情报若明确说明部队已经行动，可以增加 `aspect: ongoing` 限定并把它列入根断言。

### 13.3 因果关系

原文：

> 芯片短缺导致工厂A停产。

```yaml
events:
  - id: E1
    kind: event
    predicate:
      canonical: 短缺
      status: mapped
    frame:
      dynamics: state
      topology: intrinsic
      agency: non_agentive
    arguments:
      object: 芯片

  - id: E2
    kind: event
    predicate:
      canonical: 停产
      status: mapped
    frame:
      dynamics: change
      topology: intrinsic
      agency: non_agentive
    arguments:
      subject: 工厂A

relations:
  - id: R1
    kind: relation
    family: causal
    predicate: 导致
    arguments:
      cause: E1
      effect: E2

assertions: [R1]
focus: [E2]
```

根断言是完整因果关系，因此它同时承诺原因、结果和因果连接。若原文只是“工厂停产，可能与芯片短缺有关”，则应使用可能性限定或较弱关系，不能仍编码为无条件的“导致”。

### 13.4 否认已经撤军

原文：

> 国防部否认部队已经撤出B地区。

```yaml
events:
  - id: E1
    kind: event
    predicate:
      canonical: 撤离
      status: mapped
    frame:
      dynamics: change
      topology: transfer
      agency: agentive
    arguments:
      theme: 部队
      source: B地区

qualifications:
  - id: Q1
    kind: qualification
    family: aspect
    value: completed
    target: E1

  - id: Q2
    kind: qualification
    family: epistemic
    value: denied
    holder: 国防部
    target: Q1

assertions: [Q2]
focus: [E1]
```

该结构不会错误地断言撤军已经完成，也不会把“否认”当作撤军的生命周期阶段。

## 14. 提取与归一化流程

完整谓词表不进入提示词。推荐流程如下：

1. 阅读全文并选出一项或少量焦点事件；
2. 提取事件原文谓语、释义、FRAME 维度、核心角色和修饰信息；
3. 判断是否存在作用于事件的限定，以及限定的作用域；
4. 判断是否存在值得保留的事件关系；
5. 根据 FRAME、原文谓语、释义和领域检索谓词注册表；
6. 只把少量候选谓词提供给归一化步骤；
7. 映射成功则保存稳定 ID，无法判断则保留 `unresolved`；
8. 生成根断言和焦点列表；
9. 由确定性模板生成标准文本，并与原文含义进行一致性检查。

这一流程把“理解文章”和“匹配词表”分开。模型不需要背诵完整谓词表，也不能因为候选表缺失而任意扩充正式本体。

## 15. 渐进式可计算性

模型允许记录在不同精度层级上仍然有用：

| 层级 | 已有信息                   | 可支持的分析                             |
| ---- | -------------------------- | ---------------------------------------- |
| L0   | 原文谓语和释义             | 阅读、全文检索、向量检索                 |
| L1   | 多维 FRAME 和通用角色      | 状态、变化、作用、转移等粗粒度分析       |
| L2   | 归一化事件谓词             | 精确统计、规则匹配、同类事件比较         |
| L3   | 限定和事件关系             | 计划与事实区分、阶段判断、因果和时序分析 |
| L4   | 类型化时间、数量和领域字段 | 趋势、规模、期限和领域计算               |

未归一化谓词不会让整条记录失效，但系统必须显式降低其分析精度，不能把原文词直接当成稳定分类。

## 16. 约束与验收规则

### 16.1 结构约束

- 每个事件核只有一个主要事件谓词；
- 每个节点 ID 在一条情报内唯一；
- 所有引用必须指向同一条情报内存在的节点；
- 命题引用必须形成有向无环图；
- 第一版限定嵌套深度不超过两层；
- 一条根断言只表达一个核心判断；
- 一条情报默认选择一个焦点事件，必要时可以选择少量并列焦点。

### 16.2 语义约束

- 被引用的事件核不自动视为已经发生；
- 计划、批准、命令、否认和预测不得写成底层事件已经完成；
- 生命周期、意向、授权和认知立场不得压缩进同一个单值字段；
- 因果关系必须同时具有可识别的原因和结果；
- 不得根据常识补全原文没有提供的角色、时间或结果；
- 同一事实不得在事件核、限定和关系中重复编码；
- 来源可靠性不得与文中主体的认知立场混为一谈。

### 16.3 词汇约束

- FRAME 维度值使用封闭枚举；
- 限定 family/value 使用封闭注册表；
- 关系谓词使用小型封闭注册表；
- 事件谓词允许扩展，但运行时只能映射已有谓词或标记为 `unresolved`；
- 新谓词只能通过离线治理进入注册表；
- 组合语义优先使用命题结构表达，不注册“计划扩产”“短缺导致停产”一类可分解谓词。

## 17. 标准文本生成

标准文本生成分三步：

1. 使用事件谓词模板生成事件核文本；
2. 按固定优先级实现限定，例如意向、授权、阶段、认知立场；
3. 使用关系模板连接两个命题文本。

模板只能读取已有结构，不得补充事实。建议的默认实现顺序为：

```text
认知立场 > 可能性/条件 > 意向/指令/授权 > 生命周期 > 事件核
```

这个顺序描述作用域，不强制所有限定堆入一个句子。超过两项限定时，优先生成两个短句，以保持个人分析阅读的自然性。

标准文本不是数据真源。结构和原文片段用于审计，标准文本用于浏览、检索和导出。

## 18. 与单一 FRAME 模型的区别

| 问题             | 单一 FRAME 模型              | 受限事件命题模型                  |
| ---------------- | ---------------------------- | --------------------------------- |
| 计划收购如何分类 | ATTITUDE 与 TRANSFER 二选一  | 计划限定指向收购事件              |
| 已批准且正在执行 | 单值 stage 难以同时表达      | authorization 与 aspect 并存      |
| 短缺导致停产     | 一个复合 CAUSE 谓词          | 两个事件加一条因果关系            |
| 否认已经撤退     | 容易混淆事实与态度           | 否认限定作用于完成限定            |
| 未知长尾谓词     | 无法进入固定目录或直接发散   | FRAME 可计算，谓词标记 unresolved |
| FRAME 的职责     | 事件类型、角色和高阶语义混合 | 只描述事件核结构轮廓              |

旧有的 STATE、CHANGE、APPLY、TRANSFER 仍有价值，但被解释为常见 FRAME 维度组合；ATTITUDE、MODALIZE 被移到事件限定层；CAUSE 被移到事件关系层。

## 19. 为什么该模型适合个人情报分析

大型知识图谱通常要求复杂本体、全局实体对齐、来源融合和版本管理。个人情报分析更需要以下平衡：

- 一眼能够理解结构表达了什么；
- 不因少数长尾词汇阻塞整个抽取过程；
- 不把计划、预测和否认错误当成已经发生的事实；
- 能够逐步提高结构化精度，而不是一次建成完整本体；
- 可以通过标准文本回到自然、紧凑的分析语言。

本模型只引入三类语义对象、三个 FRAME 维度和少量封闭算子。复杂性主要来自真实内容，而不是来自大量特殊字段。它允许个人从较小的谓词注册表起步，通过未归一化候选池渐进扩展，同时始终保持上层结构稳定。

## 20. 设计结论

事件表达的核心不应是寻找一个足以容纳整句话的唯一类别，而应是区分三个问题：

1. **事件是什么**：由事件核、事件谓词、FRAME 维度和参与者角色表达；
2. **事件以何种方式成立**：由具有明确作用域的事件限定表达；
3. **事件如何与其他事件关联**：由事件关系表达。

最终结构可以概括为：

```text
情报
└── 受限命题图
    ├── 事件核：多维 FRAME + 可扩展事件谓词
    ├── 事件限定：封闭 family/value + 明确作用域
    ├── 事件关系：小型封闭关系表
    ├── 根断言：该情报实际主张的内容
    └── 焦点事件：分析人员持续关注的事件
```

这里的“受限”非常重要。模型使用命题组合获得表达力，同时通过封闭算子、有限嵌套、有向无环引用和渐进式谓词归一化控制复杂度。它不是无限开放的逻辑语言，而是一种面向情报提炼的、小型可计算语义语言。

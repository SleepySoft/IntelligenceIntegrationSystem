# Industry Prompt v4：v3 输出校验修正

> 状态：v1 仍是唯一正式版本；Shadow 从 v3 切换到 v4，采样率与同模型比较方式不变。

## 触发原因

v3 上线后首个命中 Shadow 的样本连续三次未通过结果校验，没有形成可比较资产：

1. `roles.resource` 输出单个对象，而协议要求实体对象数组；
2. `REASON` 输出 110 个字符，超过 Schema 的 100 字限制；
3. `attributes` 输出空对象，同时 `REASON` 仍超过限制。

主链 v1 正常归档，说明 Shadow 失败隔离有效；但 v3 没有产生有效样本，不能继续以原版本文本
静默修补，否则调用统计与 Prompt 身份将不可归因。

## v4 修正

- 保持 v3 的准入门槛、逐维保守评分、事件选择和解释结构不变；
- 要求 `REASON` 在输出前按字符数自检，超过 100 字时删除背景、修饰和重复事实；
- 再次明确所有角色值必须是实体对象数组，单一实体也不得直接输出对象；
- 明确 `time`、`context`、`attributes` 无内容时省略，禁止输出空对象；
- 桥接层对上述三个可选对象的 `{}` 做无损省略，但继续拒绝非空畸形对象，不猜测角色或数值语义。

## 版本与归因

- 正式池：v1；当前 Shadow 池：v4；历史可选：v2、v3；
- `sample_rate=0.25`、`comparison_mode=same_model` 保持不变；
- v3 的失败调用继续按 v3 记录，v4 从新的 Prompt 身份开始累计样本；
- 公共 Event Engine Prompt 文本和新闻 Prompt 不因本次修正发生变化。

## 1. 统计口径

- 只统计 `analysis_stats.db` 中 `shadow=0`、终态时间位于上述起止窗口内的生产记录；
- 模型必须分层比较，不把 DeepSeek 与 MiMo 样本合并；
- 成功率、首过率、错误和延迟覆盖有终态的高价值与低价值结果；
- 实体数、角色引用数及抽取质量只统计已经进入 `intelligence_v4_archived` 的高价值结果；
- Token 通过 `attempts.request_id` 关联 `ai_client_observations.db.ai_calls`。成功样本的关联率
  为 100%；“全链路 Token”包含该样本失败尝试和纠错重试；
- 本轮是随机、非配对生产 cohort。文章长度和难度差异会形成噪声，因此小样本 MiMo 只报告
  趋势，实体和角色均值还需结合固定标注集检查核心召回。

## 2. 调用结果

| 模型 | 版本 | 终态样本 | 成功率 | 首过率 | p50 | p95 | 主要错误 |
|---|---:|---:|---:|---:|---:|---:|---|
| DeepSeek `deepseek-flash` | v48 | 104 | 98.1% | 90.4% | 4,372 ms | 6,590 ms | schema 28；semantic 3 |
| DeepSeek `deepseek-flash` | v53 | 129 | 99.2% | 82.9% | 4,652 ms | 7,350 ms | schema 20；semantic 4 |
| MiMo `mimo-v2.6-flash` | v48 | 27 | 88.9% | 81.5% | 14,372 ms | 26,647 ms | schema 3；semantic 5 |
| MiMo `mimo-v2.6-flash` | v53 | 34 | 91.2% | 70.6% | 15,373 ms | 30,828 ms | schema 9；semantic 6 |

DeepSeek 的最终成功率提高 1.1 个百分点，但首过率下降 7.5 个百分点，超过设计中的
5 个百分点停止线；延迟也略有增加。MiMo 尚未达到每版本约 40 条的目标样本量，但 v53
首过率下降 10.9 个百分点，且 schema 错误由 3 次增加到 9 次，方向同样不利。

`calls/item` 不作为本次结论的主依据：纠错、模型切换及终态模型归属会使简单按最终模型
回查尝试数产生偏差。首过率直接使用终态记录的 `attempts_used`，全链路 Token 则按 UUID
和最初 Prompt cohort 汇总实际关联调用。

## 3. 归档质量与完整度

| 模型 | 版本 | 高价值 / 低价值 / 待定 | 平均实体数 | 平均角色引用数 | predicate 接地率 | time 接地率 |
|---|---:|---:|---:|---:|---:|---:|
| DeepSeek | v48 | 63 / 39 / 2 | 6.49 | 6.43 | 49.3% | 81.1% |
| DeepSeek | v53 | 78 / 50 / 1 | 6.14 | 5.71 | 66.5% | 88.1% |
| MiMo | v48 | 16 / 8 / 3 | 6.31 | 5.56 | 19.4% | 57.1% |
| MiMo | v53 | 21 / 10 / 3 | 5.62 | 5.24 | 40.0% | 76.7% |

DeepSeek v53 相对 v48：

- predicate surface 接地率提高 17.2 个百分点；
- time surface 接地率提高 7.0 个百分点；
- 有异常的高价值文档由 `10/63` 降为 `7/78`，角色类型冲突总数由 7 降为 4；
- 平均实体数下降 5.4%，平均角色引用数下降 11.2%。

接地改善说明 v52/v53 的时间门和事实接地纪律有效，但不能用“输出更少、留下的更准”替代
完整度目标。实体和角色引用两项已经达到或越过提前停止阈值。MiMo 的平均实体数下降
10.9%、角色引用数下降 5.8%，虽样本较少，仍与 DeepSeek 指向同一风险。

本报告的“角色引用数”是所有 `events[].core.roles` 引用数量，并非剔除非法绑定后的人工
标注核心角色召回。角色类型冲突下降是积极信号，但不足以解释 11.2% 的全部降幅；后续若
继续研究 v53，应从固定配对集直接核查哪些核心参与者被省略。

## 4. Token 成本

| 模型 | 版本 | 首次调用平均输入 | 首次调用输入中位数 | 每成功样本全链路 Token | Token 关联 |
|---|---:|---:|---:|---:|---:|
| DeepSeek | v48 | 9,557 | 8,691 | 13,195 | 102/102 |
| DeepSeek | v53 | 9,353 | 8,233 | 13,745 | 128/128 |
| MiMo | v48 | 9,510 | 8,607 | 10,889 | 24/24 |
| MiMo | v53 | 8,172 | 7,771 | 12,328 | 31/31 |

DeepSeek v53 的首次调用平均输入仅下降 2.1%，中位数下降 5.3%，没有达到替代条件要求的
10%；在重试计入后，每成功样本的全链路 Token 反而增加 4.2%。MiMo 首次输入下降幅度
较大，但随机小样本容易受文章长度影响，而且全链路 Token 增加约 13.2%。因此当前不能
把静态 Prompt 缩短等同为真实成本下降。

全链路汇总没有把重试限定在终态所属模型：DeepSeek v48/v53 成功样本中分别有 5/13 条
发生过跨模型尝试，MiMo v53 有 3 条。若只按终态模型过滤 attempts，会把这些换模型重试
漏掉并低估成本，因此报告采用 UUID + Prompt cohort 下的全部实际调用。

## 5. 检查点结论

v53 保住并加强了 v52 的 predicate/time 接地收益，最终成功率也未下降；但它没有完成
“恢复实体与角色完整度，同时降低全链路成本”的设计目标。当前已命中以下提前停止条件：

1. DeepSeek 平均实体数下降超过 5%；
2. DeepSeek 平均角色引用数下降超过 5%；
3. DeepSeek 首过率下降超过 5 个百分点；
4. DeepSeek 每成功样本全链路 Token 高于 v48；
5. MiMo 的完整度、首过率和 schema 错误趋势同时恶化。

因此本检查点结论为：**v53 不具备替代 v48 的条件，按既定方案应暂停新增 v53 抽样，
保留版本、统计与既有黏性任务用于审计。** 本次检查只记录结果，没有自动修改生产目录；
是否执行退出抽样应作为单独运维动作，并在执行时间点追加记录。

若后续继续探索紧凑 Prompt，不应再通过泛化的“不要省略”措辞修补。优先使用固定配对集
定位被遗漏的参与者类别，并把“核心实体召回/核心角色召回”做成可判定指标；否则随机生产
均值只能发现退化，不能准确告诉我们该补哪一条规则。

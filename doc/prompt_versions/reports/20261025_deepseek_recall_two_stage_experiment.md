# DeepSeek 单阶段 v48 与召回—编码两阶段离线实验

日期：2026-10-25（Asia/Shanghai）。

## 1. 结论摘要

本轮完成 31 篇固定原文的真实 DeepSeek 调用。结果同时支持两个判断：

1. **召回与编码分离值得继续研究**：在两种方法都成功的配对样本中，两阶段保留更多实体、
   角色绑定和第一阶段时间，说明单阶段规范编码确实可能压制事实完整度。
2. **当前两阶段实现不能直接生产化**：最终成功率由 93.5% 降至 64.5%，首过率由 58.1%
   降至 25.8%，全链路 Token 增加 45.0%，输出 Token 接近翻倍。

因此下一步不是把本实验链路接入生产，也不是继续泛化强化“不要省略”，而是先解决第二
阶段的结构可靠性和输出成本，并用语言无关的人工核心标注重新确认召回收益。生产基线保持
v48，本实验没有改变 `PromptCatalog` 或任何业务集合。

## 2. 实验设计

### 2.1 输入与调用条件

- 从 Event V4 归档只读选取 31 篇固定原文，覆盖多参与者、多事件、计划/否认、角色难映射
  和普通新闻；输入冻结于 `_data/prompt_compare/recall_two_stage_inputs.json`。
- 模型统一为 `deepseek-flash`，temperature=0，最大输出 8192 Token；API Key 只从环境变量
  读取，未写入源码、配置、实验结果或本报告。
- 单阶段直接使用 v48；两阶段第一阶段只抽事件、核心参与者和时间，第二阶段使用 v48 加
  “第一阶段核心参与者不得删除”的事实契约完成规范编码。
- 两种方法均使用现行 `core_subset_levels_reason` 协议校验；最终分析最多三次尝试，纠错
  反馈、失败调用和两次阶段调用的 Token 全部计入。
- 不写 MongoDB 业务集合，不进入生产分析队列。

复跑与汇总：

```bash
python Scripts/prompt_recall_two_stage_experiment.py --resume
python Scripts/summarize_prompt_recall_two_stage.py
```

原始结果：`recall_two_stage_results.json`；聚合结果：`recall_two_stage_summary.json`，均位于
`_data/prompt_compare/`。该目录是运行数据，不作为 git 事实源提交。

### 2.2 指标及其限制

实验记录成功率、首过率、调用次数、延迟、输入/输出/全链路 Token、实体数、角色绑定数、
未登记角色、角色类型冲突及 predicate/time surface 接地率。

参与者与时间“召回”采用第一阶段清单作为参考，通过归一化字符串在最终结果中核对。它不是
独立人工金标准，存在两个重要偏差：

- 第一阶段可能多标或错标参与者，字符串命中也不等于角色语义正确；
- 第二阶段倾向保留第一阶段原文名称，v48 更常翻译名称，因此自动核对可能低估 v48、
  高估两阶段，尤其是跨语言样本。

所以召回数字只用于发现方向，不能据此宣称真实语义召回翻倍。生产晋级前必须建立人工核心
参与者及事件归属标注。

## 3. 全样本运行结果

| 指标 | v48 单阶段 | 两阶段 |
|---|---:|---:|
| 样本数 | 31 | 31 |
| 最终成功 | 29（93.5%） | 20（64.5%） |
| 首过 | 18（58.1%） | 8（25.8%） |
| API 调用次数 | 39 | 72 |
| 输入 Token | 340,274 | 413,312 |
| 输出 Token | 152,811 | 301,581 |
| 全链路 Token | 493,085 | 714,893 |
| 每样本全链路 Token | 15,906 | 23,061 |
| 每成功样本全链路 Token | 14,321 | 23,772 |
| 累计调用耗时 | 931.1s | 1,741.1s |

两阶段总 Token 增加 45.0%，其中输出 Token 增加 97.4%。成本恶化不仅是多了一次调用，也与
第二阶段重复表达、输出变长和纠错失败有关。

### 3.1 成功样本的结构与接地（非配对，仅作描述）

| 指标 | v48 单阶段 | 两阶段 |
|---|---:|---:|
| 平均实体数 | 6.97 | 9.45 |
| 平均角色绑定数 | 6.31 | 10.15 |
| 未登记角色 | 0 | 0 |
| 角色类型冲突 | 1 | 1 |
| predicate surface 接地率 | 54.5%（36/66） | 69.1%（38/55） |
| time surface 接地率 | 78.0%（32/41） | 100%（38/38） |

两阶段没有以增加未登记角色换取更多绑定，这是积极信号；但成功样本构成不同，本表不能替代
同输入配对结论。

## 4. 同成功配对样本

19 篇样本在两种方法下均最终成功。配对比较消除了“只有容易样本能完成两阶段”造成的一部
分选择偏差。

| 指标 | v48 单阶段 | 两阶段 |
|---|---:|---:|
| 第一阶段参与者字符串匹配 | 61/147（41.5%） | 122/147（83.0%） |
| 第一阶段时间字符串匹配 | 20/36（55.6%） | 31/36（86.1%） |
| 首过 | 14/19 | 8/19 |
| 全链路 Token | 249,024 | 438,587 |

两阶段参与者字符串匹配高 41.5 个百分点、时间匹配高 30.6 个百分点，但配对全链路 Token
也增加 76.1%。参与者指标仍受第 2.2 节名称语言偏差影响；时间匹配也可能受日期表达格式
差异影响，需人工语义复核。

配对样本中，具有事件抽取结果的文档平均实体数为 7.22 → 9.42，平均角色绑定数为
6.67 → 10.00；两种方法的有抽取文档数分别为 18 和 19，因此该组数字同样只作方向性参考。

## 5. 失败分析

### 5.1 v48 单阶段

2 篇最终失败，均为核心子集结构校验问题：开放谓词字段位置错误、`agentivity` 误写为
`agency` 等。这与既有报告中的机械结构错误类别一致。

### 5.2 两阶段

11 篇最终失败：

- 6 篇 JSON 解析失败，包括空内容、未闭合字符串和分隔符错误；
- 2 篇开放 Frame/fallback roles 不合法；
- 1 篇 `REASON`、`EVENT_BRIEF` 超长；
- 1 篇使用 Registry 不支持的 phase 值；
- 1 篇把 `agentive` 填进 `frame.dynamics`。

失败并不集中于“核心参与者无法表达”，而是第二阶段在更长输入和更强保留约束下，整体
JSON/契约稳定性下降。第一阶段召回成功并不意味着第二阶段能可靠完成编码。

## 6. 与 v49—v53 的综合判断

历轮结果呈现出一致规律：

- v42 的桥接证明，**确定性代码消除机械错误的收益最稳定**；
- v52/v53 的时间门与接地纪律证明，**局部、明确、逐事件可执行的检查可以有效**；
- v49—v53 的压缩与白名单实验反复证明，**模型可通过少输出实体和绑定来降低违规风险**；
- 本实验进一步说明，把召回单独完成后，最终输出确实倾向保留更多事实；但如果第二阶段
  仍承担完整大而全契约，可靠性和成本会迅速恶化。

因此“稳定提升”的候选路径不是继续叠加 Prompt，而是：

```text
召回核心事实
  → 以不可删除的事实契约进行规范编码
  → 确定性检查事实是否守恒
  → 只修复具体缺失或非法项
```

本轮只验证了这条路径具有质量潜力，同时否定了当前朴素两阶段实现的生产可用性。

## 7. 下一步小实验

下一轮仍保持离线，并只做以下四项改动：

1. **固定人工标注**：为同一批或其中 20—30 篇标注必须保留的核心实体及事件归属，使用实体
   别名/原文 surface 同时核对，消除名称翻译造成的自动指标偏差。
2. **压缩中间结构**：第一阶段只输出必要事实、参与者原文 surface 和事件序号，不输出解释；
   第二阶段不得复述事实契约或生成额外分析文字。
3. **参与者守恒校验**：代码逐项比较第一阶段和最终输出；缺失时反馈具体事件和具体实体，
   禁止整篇无目标重试。开放谓词合法、实体仍在时不视为失败。
4. **困难样本条件触发**：先在多参与者/难映射样本上验证，普通文章继续单阶段；分别报告
   困难子集和全量成本，避免对所有文章支付两次调用。

继续实验的最低门槛：语义核心召回经人工标注确认提高，最终成功率不劣于 v48 5 个百分点，
且困难样本的每成功件全链路 Token 不高于 v48 的 1.5 倍。达不到则停止两阶段路线，不进入
生产灰度。

## 8. 可复现性与边界

- 实验脚本：`Scripts/prompt_recall_two_stage_experiment.py`；
- 汇总脚本：`Scripts/summarize_prompt_recall_two_stage.py`，包含全样本和共同成功配对口径；
- 本轮每个 UUID 只保存一次最终结果，支持断点续跑，不是多次重复的方差实验；
- 只测一个模型，结论不能外推到 MiMo、Codex CLI 或其他 DeepSeek 模型；
- 样本含跨语言文章，自动参与者匹配不是人工语义金标准；
- 不根据本轮结果修改生产 Prompt、抽样表、Registry、桥接或校验规则。

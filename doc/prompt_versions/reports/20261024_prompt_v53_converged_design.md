# Event V4 Prompt v53：完整度优先的收敛设计

日期：2026-10-24。

状态：已实现并加入生产抽样目录，v48/v53 各占一个版本槽；v52 退出抽样但保留
显式选择。2026-10-24 首检查点已经触发实体数、角色引用数、首过率和全链路 Token
停止线；检查时尚未调整生产目录。完整结果见
[v48 / v53 生产灰度首检查点](20261024_prompt_v48_v53_first_checkpoint.md)。
基线为 v52；v48 继续作为生产对照。
本设计只收敛 Prompt 文本与验证方案，不改变 Event V4 存储契约、Registry、桥接、
校验、消息布局或重试策略。

## 1. 结论先行

下一候选版本建议命名为 **v53**，采用“**v52 全文冻结，只重写角色完整度纪律**”
的单变量方案：

- 保留 v52 已验证的时间检查门、紧凑谓词目录、角色白名单及全部其他章节；
- 删除角色选择流程中的“省略实体”选项，不再把省略描述为角色不匹配时的合法兜底；
- 把处理顺序改为“先确定正文核心参与者，再选择已登记或开放谓词”，禁止反向按
  谓词目录裁剪事实；
- 将 `predicate.id=null` 的开放谓词提升为正常、平等的表达路径，而非最后补救；
- 增加逐事件核心参与者检查门，明确“schema 可选”不等于“正文明确时可以省略”；
- 不同时修改时间、评级、事件数量、示例、低价值判断或目录格式，避免再次混淆归因。

v53 的成功标准不是“更长”或“更短”，而是：**保住 v52 的时间与接地收益，消除其实体
和角色绑定损失，并使首过率与全链路 Token 至少回到可接受水平。**

前应先让 v52 退出生产随机抽样，保留显式对照；v48 不停用。

## 3. 根因判断与边界

当前最可信的机制不是“紧凑目录必然丢实体”，而是**角色白名单的显著性和兜底措辞共同
塑造了错误优化目标**：模型优先保证角色键合法，遇到难以映射的参与者时，以少输出实体
和角色绑定来降低违规风险。v52 虽增加“核心参与者不得省略”，但仍保留“非核心实体可
省略”的兜底路径，也没有要求先列核心参与者再选谓词，因此不足以扭转该行为。

同时应保留两个归因边界：

1. v48/v52 是随机生产样本而非同输入配对实验，内容差异会带来噪声；v53 必须先做同模型、
   同输入配对预检，再进入生产灰度。
2. 角色绑定数下降不能全部等同为质量下降，其中可能包含被消除的非法绑定；但实体数在
   两个模型同步下降是独立风险信号，必须结合定向标注集确认核心实体召回，而不能只看
   未登记角色计数。

因此 v53 不撤销白名单，也不通过盲目增加实体数量“刷指标”；目标是召回正文明确且对
事件理解必要的参与者，并确保每个绑定语义合法。

## 4. 冻结项与唯一变更面

### 4.1 与 v52 逐字保持一致

- IIS 价值判断、分类、六维评级、顶层 JSON、低价值原因；
- 1—3 项事件、唯一主事件、事件选择与事件关系；
- 核心子集输出结构、最小时间 `normalized + surface` 契约；
- v52 逐事件时间检查门及地点、属性、限定词规则；
- Registry 紧凑谓词目录、公共角色折叠算法及角色白名单本身；
- 稳定 `system` 与动态 `user` 的消息边界。

### 4.2 只修改命名角色纪律段

以 `prompts_event_v52.build_v52_role_section()` 对应段为唯一变更面。开放 Frame 拓扑、
实体类型限制、下令/执行/客体分离、名称消歧和完整角色落点继续保留；只重排并替换
“谓词选择—核心参与者—开放谓词—省略”的优先级和检查规则。

建议将角色段内部固定为以下阅读顺序：

1. 核心参与者完整度；
2. 已登记谓词与开放谓词的选择；
3. 角色键白名单和实体类型检查；
4. 原有角色落点与消歧规则；
5. 输出前逐事件复核。

## 5. v53 角色纪律建议文本

以下文本是设计基线，实现时允许做不改变语义的字面整理，但不得重新引入“角色不匹配时
可省略实体”的分支。

```text
## 角色与参与者完整度（输出前逐事件检查）

所有角色值都是非空实体对象数组。先从正文确定事件事实和核心参与者，再选择谓词；
不得先选谓词，再按其 roles 删减正文事实。

- 核心参与者是正文明确提及、且缺少后会改变或严重削弱事件理解的行动方、权威方、
  对象/目标、承受方，以及转移类事件的来源、去向或转移对象。不得因目录难匹配、
  角色名不确定或希望减少输出而省略核心参与者。
- 对每项事件分别核对：正文明确的核心参与者是否都已出现在语义合适的角色中；
  是否误把核心参与者留成未绑定实体；是否为了凑齐角色而补入正文未提及的实体。
  roles 在 schema 中可选，只表示正文未支持时可以没有，不表示正文明确时可以省略。
- 谓词目录用于规范表达，不用于限制可抽取的事实。已登记谓词只有在谓词含义及全部
  核心参与者的角色落点都合适时才使用。
- 若核心参与者无法合法、准确地放入当前已登记谓词，必须改用 predicate.id=null 的
  开放谓词和相应 frame，保留参与者；不得省略参与者，不得改塞入语义不符的角色，
  也不得为了使用开放谓词而删除事件。开放谓词是正常表达路径，不是低质量兜底。
- 非核心背景实体可按事件选择需要去重或省略，但“角色不匹配”不是省略理由。
```

其后紧接现有白名单和类型纪律，并将旧兜底句整体移除，避免相互矛盾：

```text
- predicate.id 非 null 时，roles 的每个键必须精确出现在“公共可选角色”或该谓词行
  的 roles 中；两处都没有的角色绝对禁止输出。
- actor、agent、subject、affected 等名称不是可跨谓词套用的通用槽位；语义组名也不是
  输出角色。无法匹配时按上节改用开放谓词，而不是自创角色或删减核心参与者。
```

保留现有实体类型、开放 Frame 拓扑和 `CORE_ROLE_LANDING_SECTION`，不复制谓词目录。

## 6. 实现约束

建议新增独立 `prompts_event_v53.py`，以 v52 构造结果为基线，仅替换唯一命名的角色纪律
段；禁止再次使用从 `## 角色` 到下一宽标题的模糊范围替换。构造器必须：

- 对目标段执行唯一性检查，数量不是 1 时立即失败；
- 复用 Registry 生成的目录、角色语义组和 `CORE_ROLE_LANDING_SECTION`，不复制枚举；
- 继续绑定 `core_subset_levels_reason` 协议，初始 `sampling=False`；
- 保持动态正文、日期和相似消息仍在 user message；
- 静态长度不超过 v48 的 75%，且相对 v52 增量尽量控制在 500 字符以内；若建议文本超过
  预算，优先合并重复措辞，不删完整度门或开放谓词规则；
- 在 v48/v52/v53 中保留稳定可审阅的章节边界，后续导出文本和快照差异只显示目标段变化。

实现后的 v53 静态 Prompt 为 16,362 字符，比 v52 增加 426 字符，是 v48 的约 75.0%
（严格小于 75%），继续满足长度约束。

本设计不要求新协议。只有模型实际输出 JSON 结构改变时才应新增协议，而 v53 明确不改
结构。

## 7. 离线验证与定向预检

### 7.1 静态回归

至少覆盖：

1. v52 的时间检查门、紧凑目录、评级、分类、低价值原因和其余非目标章节逐字保留；
2. 角色段不再包含“若实体无法……就省略该实体”或同义兜底；
3. “先参与者后谓词”“核心参与者不得省略”“无法安置必须开放谓词”均存在；
4. 白名单、行动/地点类型限制、开放 Frame 拓扑和全部角色落点仍存在；
5. 紧凑目录可无损展开回 Registry，v53 不消费运行时拼接后的模糊片段；
6. 稳定 system 消息布局、协议校验、低价值分支和导出快照不回归。

### 7.2 固定配对样本集

在 v52 的 35 条定向样本基础上扩充并固定标注，建议至少 60 条：

| 类型 | 最少条数 | 核查点 |
|---|---:|---|
| 明示过去/当前时间 | 10 | 时间召回不下降，slot 与 surface 正确 |
| 计划、未来、截止 | 10 | planned 等限定词与 expected/deadline 槽位 |
| 无明确事件时间 | 5 | 不编造时间，不使用报道发布时间 |
| 核心参与者难匹配已登记谓词 | 15 | 改用开放谓词且不丢实体/绑定 |
| 多参与者、多事件 | 10 | 逐事件归属正确，不只保护主事件 |
| 行动方与事件/设施/现象易混淆 | 10 | 类型正确，不靠错塞角色提高召回 |

每篇标注“必须出现的核心实体及其事件归属”，但不要求唯一谓词选择；同一核心事实可用
合法已登记谓词或开放谓词表达。v48/v52/v53 在同一模型、同一输入下配对运行，DeepSeek
为主，MiMo 做结构兼容和完整度复核。除最终成功率外，必须记录每次失败与纠错尝试。

预检晋级条件：

- 核心实体召回和核心角色绑定召回均不低于 v48，且相对 v52 有明确恢复；
- 时间覆盖率、时间编造率不劣于 v52；
- 未登记角色保持接近零，角色—类型冲突不高于 v48；
- 不出现以大量开放谓词规避目录、重复实体或重复角色绑定的系统性退化；
- v53 首过率不低于 v52，全链路 Token 不高于 v52。

## 8. 生产灰度与统计口径

预检通过后才把 v53 加入抽样，采用 **v48/v53 各 50%**；v52 保持显式选择。继续沿用
Prompt 首次分配写入 cache 的黏性机制，重试和重启恢复不得重新抽样。

统计沿用 v52 报告口径，并补齐以下要求：

- 调用稳定性按首次调用模型分层，同时按最初 Prompt cohort 汇总全重试结果；
- 结构质量按最终归档版本与模型分层，低价值结果另计；
- 首个检查点为每版本至少 50 条 DeepSeek，目标为每版本至少 150 条 DeepSeek，MiMo
  尽量达到每版本 40 条；不足时只报告趋势；
- 主指标是定向集核心实体/角色召回，以及生产集每篇实体数、角色绑定数和时间覆盖率；
- predicate/time surface 接地率必须与对应覆盖率同报，不能用高接地掩盖不输出；
- 成本使用每条最终成功情报的全链路输入、输出及合计 Token，包含失败尝试和纠错重试。

建议对实体数与角色绑定数同时报告原始值和“剔除非法绑定后的合法绑定值”，区分真正的
完整度恢复与重新制造非法角色。开放谓词占比只作诊断指标，不设越低越好的目标。

## 9. 停止、通过与回滚

### 9.1 提前停止

首个检查点后，出现任一情况即暂停 v53 抽样：

- DeepSeek 或 MiMo 平均实体数、合法角色绑定数相对 v48 下降超过 5%；
- 定向集核心实体召回低于 v48，或仍出现因角色难匹配而省略核心实体；
- 时间覆盖率相对 v52 下降超过 5%，或无依据时间增加；
- 首次成功率相对 v48 下降超过 5 个百分点，或 schema/semantic 错误持续明显升高；
- 未登记角色明显反弹，或角色—类型冲突高于 v48；
- 每条成功情报的全链路 Token 高于 v48。

### 9.2 通过条件

目标样本完成后，只有同时满足才考虑让 v53 替代 v48：

- 实体数、合法角色绑定数相对 v48 均不劣于 5%，定向集核心召回无系统性遗漏；
- 时间覆盖率和 surface 接地率保持 v52 的主要收益，且不增加时间编造；
- 未登记角色接近零，角色—类型冲突不高于 v48；
- DeepSeek 首过率不劣于 v48 3 个百分点，MiMo 无明显结构退化；
- 每条成功情报的全链路输入 Token 相对 v48 至少下降 10%，合计 Token 也不上升；
- 收益不能只来自 Codex CLI 等小样本或单一模型。

若完整度恢复但成本仍不达标，应接受“质量优先、保留 v48/v53 对照”的结论，不再以继续
删减抽取规则换 Token；若仅 MiMo 退化，先检查通用文本清晰度，不立即维护模型专用版本。

### 9.3 回滚

回滚只调整 `PromptCatalog` 的 sampling：v53 退出，v48 单独抽样；文本、协议和统计数据
保留。已分配 v53 的在途任务按既有审计流程完成或显式迁移，不静默改派。

## 10. 本轮明确不做

- 不修改 Registry、Event V4 schema、桥接或服务端校验；
- 不用服务端推测补齐正文未提及的实体、角色或时间；
- 不通过增加事件上限、强制所有角色必填来抬高完整度指标；
- 不同时改评级、低价值判断、时间门、谓词目录或消息布局；
- 不以最终成功率或静态字符数单独判断晋级；
- 不为单一模型维护独立业务 Prompt。

这些边界使 v53 的结果尽量只归因于“角色白名单下的参与者完整度修复”。

# Industry Prompt v2：跨类型价值校准灰度

> 日期：2026-10-28
> 状态：v1 冻结为对照，v2 与 v1 各占一个生产抽样槽；结果 schema、协议、谓词目录和评分器不变。

## 1. 当前表现复核

对生产 MongoDB 中三条典型情报重新读取归档 RATE，并用 `industry/1.0` 评分器复算：

| 样本 | Prompt / 模型 | 关键 RATE | 总分 |
|---|---|---|---:|
| 绝味食品净利创十年同期新低并伴随门店收缩 | v1 / MiMo v2.6 Flash | 实质性 8、规模 8、经营影响 6、投资可用性 6、故事性 4 | 6.8 |
| 八合里遭冒名招募、删评索费并报警 | v1 / MiMo v2.6 Flash | 实质性 8、规模 4、经营影响 6、投资可用性 6、故事性 6 | 6.4 |
| 上海印发卫星互联网三年行动方案 | v1 / DeepSeek Flash | 实质性 8、规模 8、经营影响 6、投资可用性 6、故事性 4 | 6.4 |

实际数据与“绝味、八合里低于上海”并不一致：绝味高 0.4 分，八合里与上海同分。真正异常是
八合里仅凭“行业代表性”就获得与量化产业方案相同的经营影响和投资可用性；同时 v1 的任务定义
只承认“公司行动”，却又实际接受经营结果和政府政策，缺少跨类型的统一证据标尺。

## 2. 根因

1. **准入定义与真实数据冲突**：v1 写的是“没有具体公司行动即无价值”，但绝味的核心事实是
   经营结果恶化，上海的核心事实是政府产业政策。模型只能自行突破规则，结果不稳定。
2. **证据维度相互污染**：八合里是官方确认的真实冲突，因此事实确定性可以为 8；但“官方确认”
   被连带解释成行动实质性、经营影响和投资可用性也很高。
3. **故事价值冒充决策价值**：“有行业代表性”是关注理由，不等于已经改变收入、门店、成本或
   投资假设。v1 虽声明故事性独立，却没有给出跨类型锚点。
4. **政策缺少专用传导标尺**：量化目标、作用环节、实施机制和执行进展没有被明确映射到经营影响、
   投资可用性；模型容易只因其为计划而整体保守，或只因其为官方文件而整体高估。
5. **预期差基线不严**：正文没有比较基线时，模型仍可能选择 `expected`，而不是 `unknown`。

## 3. v2 的单变量改动

v2 保留 v1 的完整输出结构、八个等级词表、Event Engine 目录、校验协议和 `industry/1.0` 评分器，
只增加判断与评级说明：

- 明确四类有效信号：公司行动、经营状态冲击、经营相关冲突、可执行产业政策；
- 经营冲突允许凭具体事实和公司应对进入情报，但没有经营结果时必须限制实质性、经营影响与投资
  可用性，故事性独立保留；
- 经营状态冲击不因“不是主动行动”而丢弃，历史低点、核心门店/订单/产量收缩可以正常升档；
- 产业政策按量化目标、实施机制、受影响环节、执行主体或进度评分，不因主体不是公司而降档；
- 八个维度逐项找证据，事实确定性不再替代行动实质性，故事性不再替代投资可用性；
- 无正文比较基线时，预期差使用 `unknown`，不得擅自使用 `expected`。

没有修改评分权重，是为了让生产差异可归因于 Prompt 校准。若本轮同时修改评分器，就无法判断
RATE 改善来自模型判断还是后处理公式。

## 4. 固定样本配对预检

使用同一个 MiMo v2.6 Flash、温度 0 对固定生产正文执行真实请求。v1/v2 均走正式 industry
校验和评分器。

| 样本 | v1 | v2 | 结论 |
|---|---:|---:|---|
| 绝味食品 | 6.6（重跑） | 6.8 | 经营状态冲击被保留，方向稳定 |
| 八合里 | 首次输出结构错误；生产归档为 6.4 | 首稿误判无价值，补充经营冲突边界后为 5.5 | 保留故事，价值维度回落 |
| 上海卫星互联网方案 | 摘要超过 100 字 | 6.4（仅临时截断超长摘要后校验 RATE） | 评级方向稳定；格式问题两版共有 |

修订后的八合里 v2 RATE 为：行动实质性 5、规模与力度 4、事实确定性 8、认知增量 6、预期差 6、
经营与战略影响 4、投资可用性 4、故事性 6。它仍然可见且有趣，但不再与已量化并有执行基础的
产业行动方案同分。

本轮预检只验证方向，不宣称三条样本具有统计显著性。上海样本的超长摘要会由生产校验反馈重试；
两版均出现，不能归因为 v2。

## 5. 灰度方法

- `PromptCatalog.sampling_versions() == [1, 2]`，随机抽样时两个版本各占一个槽，理论比例 50/50；
- 情报首次分配版本后写入 cache 的 `APPENDIX.__PROMPT_VERSION__`，即时重试、持久化重试和重启
  恢复继续使用该版本；
- 已经分配 v1 的在途情报不会迁移，灰度比例只会在新进入样本中逐渐接近 50/50；
- 归档继续记录 Prompt、模型、总分和八维 RATE，可按模型 × Prompt 分层比较；
- 使用 `Scripts/industry_prompt_gray_report.py` 输出版本样本量、价值/低价值比例、均分和维度均值；
  调用成功率、首过率和错误类型继续使用 `Scripts/analysis_model_report.py`。

## 6. 检查点与停止条件

首个检查点为每版至少 30 条完成分析的 industry 情报；正式判断至少每版 50 条，并按模型、来源和
信号类型人工分层抽查，不能仅比较总体均分。

主要观察：

- 经营冲突的行动实质性、经营影响和投资可用性是否下降，但故事性与召回是否保留；
- 经营状态冲击是否继续进入有价值分支，是否错误虚构主动公司行动；
- 量化产业政策是否稳定进入情报，经营影响和投资可用性是否有正文传导依据；
- `expected` 是否只在正文有计划/惯例基线时出现；
- v2 的首过率、schema/semantic 错误率和最终成功率是否劣化。

出现任一情况即让 v2 退出抽样、保留文本供复盘：

- 人工抽查中，有依据的经营冲突被误删超过 10%；
- 普通客诉、宣传稿或口号政策的误收率比 v1 上升超过 10 个百分点；
- 经营状态冲击被系统性判为无价值，或被虚构成主动行动；
- 首次成功率比 v1 下降超过 5 个百分点，或最终失败率明显上升；
- 同模型同来源分层后，维度变化仍与上述预期方向相反。

## 7. 本轮不做

- 不改总分权重、故事性混合比例和确定性封顶；
- 不接入公司重要性数据库或 Arachne 网络加权；
- 不修改存储 schema、前端或查询；
- 不为三个专名建立硬编码评分规则；Prompt 中使用的是可泛化事件原型。

# AI Token 消耗与新闻清洗改进待办

日期：2026-11-25

状态：待实施；本文只记录生产观测、判断和验收标准，不代表当前运行能力

## 1. 背景与结论

近期偶尔出现单日或单次 Token 消耗偏高。对 2026-11-20 至 2026-11-25 上午的
`analysis_stats.db` 与 `ai_client_observations.db` 做只读关联统计后，结论如下：

1. AA 和 Shadow 会增加产业域消耗，但不是全系统峰值的主要原因；
2. 新闻域正式分析占绝大多数 Token；
3. 输出结构校验失败引起的纠错/重试，是比实验流量更大的额外开销；
4. 个别站点把包含推荐、链接、商品列表或直播条目的大段页面内容送入模型，造成单次输入峰值；
5. 观测中的 reported token 包含缓存输入，不能直接等同于最终货币成本。

“降低消耗”不得解释为简单关闭重试或丢弃长新闻。目标是同时：

- 提高首轮输出合规率，减少本可避免的重复调用；
- 保留采集原文，只为 AI 生成确定性的、可观测的清洗投影；
- 在不丢失关键事实的前提下减少页面结构噪声和重复内容。

## 2. 生产观测基线

统计窗口内共关联到 9,253 次分析调用、约 91.29M Token：

| 来源 | 调用次数 | Token | 占总消耗 |
|---|---:|---:|---:|
| 新闻域正式分析 | 8,361 | 80.63M | 88.3% |
| 产业域正式分析 | 701 | 8.40M | 9.2% |
| 旧产业域 AA Shadow | 78 | 0.93M | 1.0% |
| 当前产业域 v2/v7 Shadow | 113 | 1.34M | 1.5% |

旧实验 `industry-v2-aa-20261112` 最后一次调用发生在 2026-11-23 08:32 UTC，此后由
`industry-v2-v7-output-20261123` 接替。当前 v2/v7 Shadow 在自身运行窗口内，相对产业域
正式链增加约 37% Token；但由于产业域总体流量较小，它只占全系统约 1.5%。因此不能用
AA/Shadow 解释全局的偶发峰值。

重试调用共 1,632 次，消耗约 16.74M Token，占总量约 18.3%。按失败调用记录汇总：

| 结果 | 调用次数 | Token |
|---|---:|---:|
| `schema_shape` | 1,613 | 16.51M |
| `semantic_rule` | 348 | 3.43M |
| 未分类错误 | 9 | 0.11M |

这里的失败 Token 包含首次失败及其后续调用，与“重试调用 Token”不是互斥口径，不能相加。

主要校验指纹包括：

- `EVENT_BRIEF:string_too_long`；
- Event Extraction 的 `agency`、`dynamics`、`predicate.surface` 缺失，或输出了旧字段；
- `dynamics` 枚举不合法；
- 使用契约不支持的 `planned`、`completed`、`ongoing` phase/intention qualifier；
- `REASON`、`EVENT_TITLE` 超长及事件数量超限。

这些问题主要属于 Prompt、模型输出与校验契约的对齐问题，正文清洗只能间接改善，不能替代
协议修复。

## 3. 超长新闻样本观察

最高输入 Token 的 12 条新闻中，10 条来自 El País；另有 ABC 长文样本。抽样特征为：

- 正文约 23K 至 45K 字符；
- El País 单篇包含约 42 至 109 行 Markdown 链接；
- 存在推荐内容、商品/优惠列表、直播条目、重复页面组件等非正文结构；
- ABC 样本约 44K 字符、763 个非空行；
- 最大单次正式新闻调用约 30.6K Token，其中输入约 29.7K Token。

当前旧式 RSS 任务通常执行“CSS 选择正文容器 → HTML 转 Markdown → Unicode 规范化 → 从尾部
硬截断”。El País 和部分新闻任务允许最多约 51,200 字符。这个流程能防止无限输入，但不会
识别容器内部的相关推荐、链接列表、双端重复 DOM 或长列表，也不能保证硬截断前留下的是最有
价值的事实。

## 4. 待办 A：降低无效重试

优先级：P0。预期收益高于关闭 Shadow。

### A1. 对齐 Prompt 与服务端契约

- 从校验指纹反推 v48 中仍可能诱导旧字段或非法枚举的说明和示例；
- 明确 `frame.agency`、`frame.dynamics`、`predicate.surface` 的必填结构；
- 明确 qualifier 的允许类型和值，禁止把自然语言阶段词放入不支持的枚举；
- 对 `EVENT_BRIEF`、`REASON`、`EVENT_TITLE` 给出比服务端硬上限更保守的输出预算；
- 修改前后使用固定回放集做同模型 A/B，不直接以生产首过率波动判断效果。

### A2. 只做可证明安全的服务端归一化

可以评估：

- 清理 JSON fence、空白和确定性的旧字段别名；
- 对展示型文本做边界内、安全且可记录的长度归一化；
- 将完全等价的枚举拼写映射到契约值。

不得自动猜测缺失事件角色、谓词、时态或实体，也不得用截断掩盖事实结构不完整。归一化前后
必须记录原因和计数，仍不合格时保留现有反馈纠错路径。

### A3. 验收指标

- 新闻域首过率按模型、Prompt 版本分别统计；
- `schema_shape` 调用数和 Token 至少下降 30%；
- `EVENT_BRIEF:string_too_long` 不再是第一大失败指纹；
- 终态成功率不得下降，事件抽取质量不得因“宽松校验”虚高；
- 重试策略保持兜底能力，验收前不直接减少最大重试次数。

## 5. 待办 B：建立新闻分析清洗投影

优先级：P0/P1。先治理峰值来源，再建设共享能力。

### B1. 数据边界

- MongoDB cache 中的采集正文继续作为原始输入事实保存；
- 清洗结果作为调用 AI 前的 `analysis_content` 投影，不原地覆盖采集正文；
- 归档中的 `APPENDIX.RAW_DATA` 仍保留原输入，便于审计和重新分析；
- 清洗器必须确定性、可测试，不增加一次 LLM“预清洗”调用；
- 通用清洗能力应通过领域前处理/协议边界接入，不在 Prompt 拼接函数中偷偷修改所有领域内容。

### B2. 第一批站点专项治理

优先处理 El País 和 ABC：

- 收紧正文 CSS selector；
- 使用 `exclude_selectors` 移除分享、订阅、推荐、广告、商品卡片、评论、页脚及重复组件；
- 为直播页、列表页、商品/优惠页建立独立规则，不把它们当成普通单篇报道；
- 用保存的生产样本做离线回归，确认标题、导语、事实段落和关键引语仍然保留。

### B3. 共享 Markdown 后处理

- 删除图片语法和裸 URL；Markdown 链接保留可读锚文本；
- 规范空白和碎片行；
- 合并完全重复及高置信近似重复段落；
- 清除重复标题、作者栏、发布时间和确定性的站点模板语句；
- 识别“相关阅读、更多内容、订阅”等高置信尾部边界；
- 不采用“短于 N 字符即删除”的通用规则，避免误删数字、时间、短引语和直播事实。

### B4. 超长内容预算

仅对送入 AI 的投影实施预算，不限制原文存储：

- 普通报道按标题、导语和正文顺序保留；
- 长篇报道按段落选择，优先保留包含实体、日期、数字、引语及因果关系的段落；
- 直播报道保留背景摘要和最近更新，并明确记录选择策略；
- 禁止简单从字符串尾部硬截断；若不得不截断，应在段落边界执行并记录 `truncated=true`；
- 预算应优先基于模型 Token 估算，而不是对所有语言使用同一字符数。

### B5. 观测与安全回退

每次清洗至少记录：

```text
raw_chars, cleaned_chars, estimated_input_tokens,
compression_ratio, duplicate_paragraphs, link_lines,
truncated, cleaning_rules, source_host
```

当清洗后内容过短、压缩率异常或标题/导语消失时，回退到保守投影并报警。不得把清洗失败
静默转换成低价值新闻。

### B6. 验收指标

- El País/ABC 的 p95 输入 Token 明显下降，目标先设为至少 30%；
- 全局最大单次输入不再由页面推荐或链接列表主导；
- 清洗后为空、关键事实丢失和误截断比例通过固定样本回归为零；
- 新闻域终态分类、实体和事件召回不出现显著退化；
- 记录按来源的原始/清洗长度分布，以便继续定位异常站点。

## 6. 实施顺序

1. 建立固定回放样本和清洗观测字段；
2. 修复 El País、ABC 站点提取规则；
3. 修复最高频 Prompt/schema 不一致并做离线 A/B；
4. 引入共享 Markdown 后处理；
5. 引入段落级、Token-aware 的超长内容预算；
6. 运行一段时间后重新比较正式链、重试、AA/Shadow 各自 Token 占比。

在完成第 1 步以前，不应仅依据单日账单调整 Shadow 抽样率；在完成 A/B 验证以前，也不应通过
放宽 schema 或关闭重试来制造表面上的首过率提升。

# Event V4 v51：v48 角色目录单变量压缩灰度

## 目标

v50 的生产样本表明，Registry 驱动的角色白名单和实体类型纪律能降低角色错误；
但 v49/v50 对整个 Prompt 的同步重写也造成事件、实体和时间抽取完整度下降，无法
把收益与退化准确归因。

v51 因此回到 v48，只替换谓词/角色章节：

- 完整保留 v48 的价值判断、评级、事件选择、JSON 示例、时间、地点、属性、
  限定词、事件关系和低价值原因；
- 将逐谓词重复展开的目录替换为 `build_compact_predicate_catalog()` 生成的公共角色
  折叠目录；
- 将原角色说明替换为 v50 已验证的角色白名单、角色语义类型和开放谓词纪律；
- v50 退出生产抽样，但仍可显式选择用于回滚和人工对照。

默认 Registry 下，v51 静态 Prompt 为 15,333 字符，v48 为 21,822 字符，缩短
约 29.7%；两者使用完全相同的输出协议和服务端校验链。

## 灰度与停止条件

生产随机抽样版本为 v48/v51，各 50%。评估必须按模型分层，并至少观察：

- 成功率、首次成功率、schema/semantic 错误和调用次数；
- 未登记角色、角色—类型冲突；
- 每篇事件数、实体数以及带时间对象的事件比例；
- predicate/time surface 接地率；
- 实际输入、输出、缓存 Token 和延迟。

若事件数、实体数或时间覆盖率相对 v48 下降超过约 5%，或错误率明显升高，应停止
v51 灰度。角色异常接近 v50、完整度接近 v48且实际 Token 下降，才可继续扩大样本。

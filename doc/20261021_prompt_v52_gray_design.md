# Event V4 v52：紧凑目录的完整度修复与可归因灰度设计

## 1. 结论先行

v52 以 v51 为基线，不回到另一套 Prompt，也不再压缩新章节。它只修复 v51 已暴露的
两个完整度问题：

1. 恢复 v48 在角色段中的全部“角色落点”规则，并增加逐事件时间检查门；
2. 修正角色白名单纪律，核心参与者无法放入已登记谓词时必须改用开放谓词，不能为了
   通过白名单而直接丢弃核心实体。

v52 继续保留 v51 已验证有效的紧凑谓词目录和角色白名单。目标不是追求更短，而是在
保留约 15%实际输入 Token 收益的同时，把时间、实体完整度恢复到 v48 水平。

生产灰度前必须先解决“持久化重试重新随机选择 Prompt”的归因问题。v52 初次实现时
只注册为可显式选择、`sampling=False`；基础设施和离线检查通过后，才把生产抽样从
v48/v51 切换为 v48/v52。

## 2. v51 差异复盘

### 2.1 已确认收益

- DeepSeek 首次输入 Token 相对 v48 下降 17.2%，MiMo 下降 12.1%；
- 两个模型的未登记角色均降为零；
- DeepSeek 首次成功率基本持平。

### 2.2 已确认退化

- DeepSeek 事件时间覆盖率相对下降约 15%—19%（不同统计时点略有浮动）；
- MiMo 时间覆盖率也同方向下降，且首次成功率、schema 错误和重试次数变差；
- DeepSeek 平均实体数下降 4.6%，角色—类型冲突未随未登记角色一起改善。

### 2.3 代码级原因

v51 用 `## 角色` 到 `## 时间、地点和属性` 作为整段替换边界。新段保留了白名单、
开放 Frame、下令/执行方区分和实体消歧名称，却漏掉 v48“角色落点”中的两条规则：

- 计划、拟议、威胁和要求必须加限定词，时间使用 `expected_start_time` 等预期槽位；
- 特定机构作出的判断必须用带 `by` 的 epistemic 限定词保留主体。

第一条直接削弱了未来事件与预期时间槽的联系。不过生产数据继续分层后发现，它不是
唯一原因：DeepSeek 非计划事件的时间覆盖率也由约 48.8%降至 39.7%。因此只补回原句
不足以解决问题，还需要明确“`time` 是条件必填，而不是可随意省略”。

另一个风险来自 v50/v51 的指令：“实体无法放入合法角色时，就省略实体或改用开放
谓词”。模型可能优先选择更省事的“省略实体”，这与实体数下降方向一致。白名单应
限制角色名，而不应奖励信息丢失。

## 3. v52 Prompt 设计

### 3.1 保持不变

以下内容与 v51 逐字保持，不在 v52 同时试验：

- v48 的价值判断、分类、评级、输出 JSON、低价值原因和缓存友好消息布局；
- 核心子集输出协议及服务端桥接/校验链；
- v51 的 Registry 紧凑谓词目录；
- v51 的已登记谓词角色白名单、角色语义类型限制和开放 Frame；
- 事件选择数量、地点、属性、限定词目录和事件关系规则。

### 3.2 完整恢复角色落点

不要再手工重写 v48 角色落点的子集。v52 构造器应复用或完整保留 v48 的全部规则：

- 下令方、执行方和对象的区分；
- 调查/审查/评估的真实客体；
- 实体名称中的消歧类别词；
- 计划/拟议事件的限定词和预期时间槽；
- 特定机构判断的 epistemic 主体。

实现时应把这些规则提取成命名章节或独立构造函数，由 v48、v52 共用，避免再次靠
字符串范围替换丢句子。

### 3.3 改写“无法安置角色”的纪律

把 v51 的：

> 若实体无法放入当前谓词的合法角色，就省略该实体或改用开放谓词。

改为以下语义：

- 主事件的行动方、对象等核心参与者不得为了满足白名单而省略；
- 核心参与者无法放入当前谓词合法角色时，必须改用 `predicate.id=null`，按开放
  Frame 表达；
- 只有不影响事件事实的非核心实体才可省略；
- 禁止为了保留已登记谓词而把实体塞进语义不符的合法角色。

这仍然维持“未登记角色为零”的机械纪律，同时减少实体丢失和角色—类型冲突。

### 3.4 增加逐事件时间检查门

在“时间、地点和属性”标题后、时间 JSON 格式前增加一段短指令：

> 对每项事件分别检查正文是否明示其发生、开始、结束、生效、截止或预期时间。若能
> 可靠规范化，`time` 对该事件为必填；只有正文没有事件时间或无法可靠规范化时才可
> 省略。报道发布时间不能冒充事件时间。已发生事件优先使用 event/start/end/effective，
> 计划或预期事件使用 expected_start/expected_end，截止要求使用 deadline；surface
> 必须逐字来自正文。

“可选”只表示 schema 允许缺失，不表示发现了可靠时间仍可省略。该检查应针对每个
事件，而不是一篇文章只输出一个时间。

### 3.5 长度约束

v52 只增加短检查门并恢复遗漏规则，不复制谓词目录。实现后必须记录实际字符数：

- 静态 Prompt 长度不高于 v48 的 75%；
- 与 v51 相比增量应控制在 1,000 字符以内；
- 消息布局继续保持稳定 system 前缀，不把日期或正文移回 system message。

## 4. 灰度基础设施前置修复

### 4.1 Prompt 分配必须黏住情报

目前一次 `_analyze_v4_with_retry` 内的三次尝试会固定 Prompt，但任务进入持久化重试
队列后，再次执行会重新随机抽样。首轮窗口内 378 条情报中有 5 条因此跨过两个 Prompt
版本，无法严格归因。

修复方案：

1. 情报首次进入分析时，从 sampling 版本中随机选择一次；
2. 把版本写入 cache 的 `APPENDIX.__PROMPT_VERSION__`；
3. 同一情报的即时重试、持久化重试和恢复回放都复用该版本；
4. 成功归档时沿用同一字段；显式人工调试和 shadow 版本不改写生产分配；
5. 老 cache 没有该字段时，在第一次新分析时分配并持久化。

切换抽样表后，已分配旧版本的在途任务仍按旧版本完成；统计按首次分配时间和版本
过滤，不能把它们误算进新实验。

### 4.2 模型切换的统计边界

网络/限流重试仍允许换客户端和模型，这是生产容错所需。评估必须同时提供：

- 按首次调用模型分层的首次成功率、首次错误和首次延迟；
- 按最终成功模型分层的归档结构质量；
- 按最初 Prompt cohort 汇总的全重试 Token、调用次数和最终成功率。

不要把最后一次模型当成整条情报唯一使用过的模型。

## 5. 实施阶段

### 阶段 A：构造与回归测试，不生产抽样

1. 新增独立 `prompts_event_v52.py`，以 v51 为基线构造，禁止从运行中字符串做宽范围
   模糊替换；章节标记必须唯一，不唯一立即失败。
2. v52 注册到 PromptCatalog，协议仍为 `core_subset_levels_reason`，初始
   `sampling=False`。
3. 增加静态回归：v48 的五条角色落点规则在 v52 全部存在；时间检查门存在；紧凑
   目录可无损展开；输出协议、消息布局和非目标章节不变。
4. 增加快照式差异测试，只允许角色纪律和时间检查两个命名章节与 v51 不同。
5. 实现并测试 Prompt 黏性分配，覆盖即时重试、持久化重试、重启恢复和旧 cache。

### 阶段 B：小样本定向预检

从既有归档中固定选择少量、可重复的用例，不修改权威数据：

- 明示过去时间 10 条；
- 计划/未来/截止时间 10 条；
- 没有明确事件时间 5 条，检查是否编造；
- 角色容易冲突或核心实体难放入已登记谓词 10 条。

在同一模型上对 v48/v52 做配对比较。优先使用 DeepSeek；MiMo 只做 10 条结构兼容
冒烟，避免在已知不稳定模型上过早消耗额度。预检要求：有明确时间的样本召回不低于
v48、无时间样本不增加编造、未登记角色为零、核心实体不因白名单丢失。

### 阶段 C：生产灰度

预检通过后：

- v51 设为 `sampling=False`，保留显式回放；
- v48/v52 各 50%，按情报首次分配并持久化；
- 记录准确启用时间，重启服务后确认 sampling 表和健康检查；
- 首个检查点为每个版本至少 50 条 DeepSeek 首次样本；
- 目标样本为每版本至少 150 条 DeepSeek，以及自然路由下每版本至少 40 条 MiMo；
- 达到目标或运行 24 小时二者先到即评估。MiMo 未达到 40 条时只报告趋势，不单独据此
  宣告通过。

## 6. 评估指标

### 6.1 主要质量指标

- 带可靠时间对象的事件比例，按文章聚类 bootstrap 计算置信区间；
- 定向标注集上的明确时间召回率和无依据时间率；
- 每篇事件数、实体数、每事件角色绑定数；
- 未登记角色数/百事件、角色—实体类型冲突数/百角色绑定；
- predicate/time surface 接地率。

仅看 time surface 接地率会漏掉“干脆不输出时间”的问题，必须与时间覆盖率同时报告。

### 6.2 运行与成本指标

- 首次成功率、schema/semantic 错误率；
- 最终成功率、每条调用次数、重试后仍在 pending 的比例；
- P50/P95 延迟；
- 首次输入/输出/缓存 Token；
- **每条最终成功情报的全链路 Token**，包含失败尝试和纠错重试。这是成本主指标，
  防止 Prompt 虽短却因重试增加而实际更贵。

## 7. 判定与回滚

### 7.1 提前停止

达到首个检查点后，出现任一情况即暂停 v52 抽样并保留数据：

- DeepSeek 时间覆盖率相对 v48 下降超过 10%；
- 首次成功率下降超过 5 个百分点，或 schema 错误持续明显升高；
- 平均事件数、实体数或角色绑定数下降超过 5%；
- 未登记角色重新出现明显反弹，或角色—类型冲突高于 v48；
- 每条成功情报的全链路 Token 不降反升。

### 7.2 通过条件

目标样本完成后，v52 才可考虑替代 v48：

- 时间覆盖率、事件数和实体数相对 v48 均不劣于 5%；
- 未登记角色维持接近零，角色—类型冲突不高于 v48；
- DeepSeek 首次成功率不劣于 3 个百分点；MiMo 不出现 v51 式明显结构退化；
- 每条成功情报的全链路输入 Token 至少下降 10%；
- 定向标注集未发现时间编造或核心实体系统性遗漏。

若质量恢复但 MiMo 仍明显退化，不立即为模型维护两套业务 Prompt。先检查紧凑目录
格式是否可做模型无关的清晰化；只有确认属于稳定模型能力差异后，才讨论按 client
capability 选择 Prompt。

### 7.3 回滚方式

回滚只改变 PromptCatalog 的 sampling 标记：v52 退出、v48 单独抽样；v52 文本和协议
继续保留用于复盘。已黏住 v52 的在途任务可以完成，也可以由运维明确执行一次 cohort
迁移；不得在无审计情况下静默改派。Prompt 子系统故障不得影响 IIS Web 和非 AI 功能。

## 8. 本轮不做的事情

- 不改变 Event V4 存储契约、桥接逻辑或校验规则；
- 不扩大一至三项事件的数量限制；
- 不为 MiMo 单独维护 Prompt；
- 不用服务端猜测补齐正文时间；
- 不把报道发布时间写成事件时间；
- 不在 v52 同时改评级、低价值判断、JSON 示例或谓词 Registry。

这些边界保证 v52 的结果仍能主要归因于“紧凑角色目录下的完整度修复”。

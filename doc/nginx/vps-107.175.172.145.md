## 4. 家庭动态 IP 更新机制

家庭设备每分钟请求：

```text
https://sleepysoft.org/ddns/update
```

Nginx 将请求转给 `127.0.0.1:9000`。`home_ddns.py` 从 `X-Real-IP` 读取来源公网 IPv4，原子更新：

```nginx
upstream home_backend {
    server <家庭公网 IP>:25000;
}
```

随后执行 `nginx -t` 和 `systemctl reload nginx`。检查时家庭设备持续上报 `223.166.145.161`，生成文件中的地址与之一致。

旧文档中使用的 `sleepysoft.asuscomm.com` 当时解析为 `223.166.145.200`，与自建上报结果不一致。VPS 当前以自建上报地址为准，不再通过 ASUS DDNS 解析 upstream。

## 5. 2026-10-13 发现的问题

### 5.1 主站 504 的故障点在家庭侧

从 VPS 直接检查：

- `223.166.145.161:25000` TCP 可连接。
- 该端口使用明文 HTTP，不是 HTTPS。
- 请求 `Host: sleepysoft.org` 时，下游 Nginx 返回 `504 Gateway Time-out`。
- `223.166.145.200:25000` 从 VPS 连接超时。

因此当前公网 VPS、Cloudflare 到 VPS、动态 IP 上报以及 VPS 到家庭入口的 TCP 链路都在工作；主要故障位于 `223.166.145.161:25000` 后面的家庭网关/内部应用链路。下游响应头显示 `nginx/1.18.0 (Ubuntu)`，与旧文档中的“Windows Nginx”描述不同，家庭侧部署可能已经调整。

### 5.2 Certbot 处于 failed，但正式站点证书有效

- `sleepysoft.org`：有效至 `2027-01-05 21:48:09 UTC`。
- `impart.today`：有效至 `2026-11-27 03:22:49 UTC`。
- 已废弃的 `google.sleepysoft.org` 与 `gemini.google.sleepysoft.org` 证书已于 2026-02-09 过期，续期挑战持续失败，导致整个 `certbot.service` 显示 failed。

正式站点暂未受影响，但应清理废弃 renewal 配置，避免真正需要续期时被失败噪音掩盖。

### 5.3 DDNS Token 会进入访问日志

当前 Token 放在 query string 中，因此完整凭据会写入 `/var/log/nginx/access.log`。后续应：

1. 轮换现有 Token；
2. 改用 `Authorization` 或 `X-DDNS-Token` 请求头；
3. 为 `/ddns/update` 单独设置 `access_log off` 或使用不记录敏感字段的日志格式；
4. 如继续允许直连 VPS，限制请求频率并考虑来源约束。

### 5.4 系统生命周期与暴露面

- Ubuntu 20.04 已结束标准支持，内核和 Nginx 版本较旧。
- 未安装 UFW，检查时也没有可用的 `iptables-save` 命令。
- Nginx 全局配置仍声明 TLS 1.0/1.1；正式站点因引入 Certbot 参数而使用 TLS 1.2/1.3。
- 默认 HTTP 站点仍存在；443 没有显式 `default_server`，未知 Host 可能落入第一个 TLS 站点并打到家庭 upstream。

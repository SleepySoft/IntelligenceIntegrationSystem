## 2. 443 端口与 SNI 分流

公网 `443` 先进入 Nginx stream，配置位于 `/etc/nginx/stream.d/`：

```text
公网 :443
  -> ssl_preread
      |- SNI = sleepysoft.dev -> 127.0.0.1:8443 (Xray)
      `- 其他 SNI            -> 127.0.0.1:9443 (Nginx HTTP TLS 站点)
```

内层站点包括：

- `/etc/nginx/sites-enabled/ddns.sleepysoft.dev`
- `/etc/nginx/sites-enabled/yiflow.sleepysoft.dev`
- `/etc/nginx/sites-enabled/default`

stream 转发当前未启用 PROXY protocol，因此内层 Nginx 看到的连接来源是 `127.0.0.1`。DDNS 客户端
必须显式提交经过校验的公网 IPv4，不能依靠内层站点的 `$remote_addr` 推断设备公网地址。

## 3. sleepysoft.dev 的真实 DDNS

与 `sleepysoft.org` 的动态 Nginx upstream 不同，本机的 `ddns-server` 会调用 Porkbun API，真实创建或
更新 `sleepysoft.dev` 的 A 记录。

关键位置：

| 内容 | 路径 |
| --- | --- |
| 服务 | `/etc/systemd/system/ddns-server.service` |
| 程序 | `/opt/ddns-server/server.py` |
| 管理网页 | `/opt/ddns-server/web/` |
| 配置与令牌 | `/etc/ddns-server/config.json` |
| 最近上报状态 | `/etc/ddns-server/state.json` |
| 公网入口 | `https://ddns.sleepysoft.dev/` |

当前记录前缀：

- `home.sleepysoft.dev`
- `yiflow-home.sleepysoft.dev`

每个设备前缀使用独立令牌。客户端通过 `X-Key` 请求头提交令牌，令牌不得放在 URL、日志或本文中。
增删、轮换令牌优先使用管理网页；CLI 入口为：

```bash
python3 /opt/ddns-server/server.py --help
```

## 4. YiFlow 当前生产拓扑

```text
浏览器
  -> yiflow.sleepysoft.dev:443
  -> 本 VPS Nginx（TLS）
  -> yiflow-home.sleepysoft.dev:26000
  -> 家庭路由器端口映射 26000 -> 192.168.50.240:9100
  -> 家庭主机 yiflow.service
```

VPS 站点配置：

```text
/etc/nginx/sites-available/yiflow.sleepysoft.dev
```

该配置使用 Nginx `resolver` 和变量形式的 `proxy_pass`，按 DNS TTL 重新解析
`yiflow-home.sleepysoft.dev`。不要改成只在 Nginx 启动或 reload 时解析一次的静态 hostname
upstream，否则家庭公网 IP 变化后会继续访问旧地址。

家庭主机每分钟运行 `yiflow-ddns.timer`，从独立 HTTPS 地址获取并校验公网 IPv4，然后带专用令牌
上报给 `ddns.sleepysoft.dev`。令牌保存在家庭主机 `/etc/yiflow/ddns.token`，权限必须为 `0600`。

VPS 原有 YiFlow 应用已于 2026-11-12 停用：

- `yiflow.service`：`inactive`、`disabled`，重启 VPS 不会自动启动；
- 旧程序、环境和数据仍保留在 `/opt/yiflow`、`/etc/yiflow`、`/var/lib/yiflow`；
- 切换前的 Nginx 配置备份为
  `/etc/nginx/sites-available/yiflow.sleepysoft.dev.bak-20261112-1655`；
- 不得删除旧数据，直至家庭生产环境完成足够时间的运行验证并另行确认清理。

若需要紧急回退到 VPS 本机实例，必须先核对数据库新旧差异，不能直接启动旧服务造成数据分叉。

## 5. 与 sleepysoft.org 的区别

`sleepysoft.org` 所在的 `107.175.172.145` 接收家庭来源 IP 后，直接重写自己的 Nginx
`home_backend` 并 reload；它没有为家庭地址创建 DNS 记录。该机制服务于 IIS 的家庭回源。

`107.175.194.148` 上的 `ddns-server` 才是真正的 Porkbun DDNS。YiFlow 使用后者的独立
`yiflow-home` 记录，不依赖 ASUS DDNS，也不依赖 org VPS。

## 6. 常用检查与变更流程

只读检查：

```bash
systemctl is-active nginx ddns-server xray tailscaled
systemctl is-active yiflow || true
systemctl is-enabled yiflow || true
ss -lntp
nginx -T
journalctl -u ddns-server -n 50 --no-pager
getent ahostsv4 yiflow-home.sleepysoft.dev
curl --noproxy '*' -fsS http://yiflow-home.sleepysoft.dev:26000/api/v1/health
curl --noproxy '*' -fsS https://yiflow.sleepysoft.dev/api/v1/health
```

修改 Nginx 时：

1. 先备份目标文件；
2. 修改 `/etc/nginx/sites-available/`，不要直接改 `sites-enabled` 符号链接；
3. 执行 `nginx -t`；
4. 仅在检查通过后执行 `systemctl reload nginx`；
5. 同时验证家庭回源健康端点和公网 HTTPS 健康端点。

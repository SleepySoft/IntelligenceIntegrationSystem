# IIS 核心事件表达规范

核心提炼、FRAME、stage、角色、谓词与标准文本生成

## 1. 文档目标与适用范围

本规范用于指导 AI 从一篇情报中提炼最重要、最新且最具持续跟踪价值的核心事件，并以统一、稳定、可计算的结构保存和表达。默认输出一项核心事件；文章确实包含两项相互独立且重要性相当的事件时，可以输出第二项。

提炼关注事件身份、实际主体、核心对象、当前阶段和少量决定性信息，不追求穷尽正文中的每个动作、表态、背景和结果。系统以 FRAME 描述顶层语义结构，以 predicate 标识可持续跟踪的事件身份，以 stage 描述生命周期进展，并通过 roles、time、context 和 fields 保存必要信息。

## 2. 核心提炼原则

- 先理解全文，再选择能够代表文章信息增量的核心事件。标题、导语和正文共同用于判断核心。历史回顾、行业常识、重复说明和一般评论通常不进入核心表达。

- 实际发生的行动或变化优先级较高，已经作出的决定次之，计划、预测和判断随后。文章价值恰好来自计划、预测或判断时，应直接保留相应事件。

- 核心谓语表达被持续跟踪的事件本身。公司宣布将收购另一家公司时，通常使用“收购”；指挥部要求部队撤退时，通常使用“撤退”。宣布、要求、批准、开始和完成等词语多数用于确定事件阶段、门槛或信息来源。

- 每条记录只表达一项核心事件，并只选择一个 FRAME。行动、结果和原因同时出现时，根据全文焦点选择最能代表信息价值的一项，其余内容只在会改变理解时保留。

- 决定性补充优先进入 stage、关键门槛、数量、时间、地点或结果等结构化字段。普通扩展字段只容纳低频且暂时无法统一表达的信息。

- 字段缺失时使用 unknown 或留空，具体取决于字段协议。禁止凭借常识补全原文没有给出的事实。

## 3. 总体语义模型

FRAME、predicate 与 stage 分别回答不同问题。FRAME 回答事件采用哪一种基本语义结构；predicate 回答系统正在跟踪哪一种具体事件；stage 回答该事件当前走到生命周期的哪一步。三者相互配合，角色和补充字段承载具体事实。

| **组成**       | **职责**                                                                                       |
| -------------- | ---------------------------------------------------------------------------------------------- |
| FRAME          | 七种固定顶层语义结构之一，定义基本角色、角色语义、结构校验和跨谓语查询协议。                   |
| predicate      | 可持续跟踪的统一谓语，定义事件含义、事件身份、适用角色、适用 stage、别名、扩展字段和文本模板。 |
| specific       | 可选领域细化标签，用于检索、统计、自然表达和候选谓语演进，不承担事件身份的主要匹配责任。       |
| stage          | 统一谓语所代表事件的当前生命周期阶段。                                                         |
| roles          | FRAME 结构中的参与者、对象、关系端点及结构性地点。                                             |
| time           | 具有严格语义的事件时间、开始时间、结束时间、生效时间、期限、预计时间和观察时间。               |
| context        | 不参与核心语义结构的发生环境，第一版主要保存 event_location。                                  |
| fields         | 谓词声明的金额、比例、审批状态、方法、条件、范围和其他稳定、可计算信息。                       |
| custom_fields  | 暂未注册的临时扩展信息，必须提供 kind、value 和 surface。                                      |
| canonical_text | 由确定性模板生成的标准文本，强调准确、稳定和可复现。                                           |

## 4. 七种 FRAME 概览

| **FRAME** | **归类标准**                                                                             | **基本角色**                          |
| --------- | ---------------------------------------------------------------------------------------- | ------------------------------------- |
| STATE     | 核心内容说明主体当前具有某种状态、属性、关系、能力或处境。                               | subject、state、counterpart、scope    |
| CHANGE    | 核心内容说明主体的状态、数量、能力、身份、阶段、关系或存在情况发生变化。                 | subject、dimension、from、to、agent   |
| TRANSFER  | 核心内容说明人员、物资、资金、信息、权利、责任、订单、位置或控制关系从来源端转向目标端。 | theme、source、destination、authority |
| APPLY     | 核心内容说明行动者对目标实施行动、操作、作用或实际努力。                                 | actor、target、instrument、result     |
| MODALIZE  | 核心内容说明控制者改变主体实施行为的许可、义务、承诺、限制或可行空间。                   | controller、subject、action、scope    |
| ATTITUDE  | 核心内容说明个人、组织或系统对事件或命题作出判断、预测、计划、怀疑、担忧或评价。         | holder、content、basis、confidence    |
| CAUSE     | 核心内容说明一个因素或事态导致、促进、阻止、延缓、加剧或缓解另一个结果。                 | cause、effect、mechanism、strength    |

## 5. FRAME 角色与统一谓词目录

本目录按七个固定 FRAME 展开。每个 FRAME 使用一套跨领域角色定义；具体谓词继承这些角色，并仅在确有必要时补充特殊约束。通用跨领域谓词用于归一化常见表达，特定领域谓词用于保留产业、军事、政策、科技和金融等场景中的核心语义。

### STATE

**描述：**表达某个实体、属性、能力、身份、关系或整体事态在特定时间范围内成立，核心关注当前是什么、具有什么或与谁存在何种稳定关系。

#### 角色

- subject: 状态、属性、能力、身份或关系的主要承载者，也是该状态持续跟踪的核心对象。

- state: 在指定时间范围内成立的状态、属性值、能力、身份或关系类型。

- counterpart: 当 state 表达主体之间的关系时，与 subject 共同构成该关系的另一端对象。

- scope: 状态适用的对象范围、地域范围、业务范围或条件范围，仅在其决定状态含义时提取。

#### 通用跨领域谓词

- 处于：主体当前处于某种明确状态或情形。

- 拥有：主体当前持有、占有或依法享有某个对象、资源或权益。

- 控制：主体当前能够决定或支配另一对象、资源、区域或组织。

- 属于：主体当前是某个组织、集合、类别或体系的成员。

- 位于：主体当前存在于某个地点、区域或位置。

- 依赖：主体的运行、供给或目标实现持续依靠另一对象或条件。

- 具备：主体当前拥有某项能力、资质、资源或条件。

- 符合：主体当前满足某项标准、规则、要求或技术条件。

- 连接：两个对象之间当前存在通信、运输、网络或结构连接。

- 有效：协议、政策、许可、资格或规则当前具有约束力或适用性。

#### 特定领域谓词

- 持有股权：产业/金融：主体当前持有企业股权或其他权益。

- 具备产能：产业：工厂或企业当前具有特定产品和规模的生产能力。

- 依赖供应商：产业：企业持续依赖特定供应商提供关键投入。

- 占有市场份额：产业：企业或产品当前占有特定市场比例。

- 处于满产：产业：工厂当前以接近设计上限的负荷运行。

- 部署于：军事：部队、装备或系统当前位于并配置在指定区域。

- 控制领土：军事：一方当前实际控制特定地域或关键位置。

- 保持战备：军事：部队当前维持某一战备等级或响应能力。

- 隶属于：军事/组织：单位当前接受特定上级组织或指挥体系管理。

- 处于包围：军事：部队、设施或区域当前受到周边封锁或围困。

- 政策有效：政策：某项政策、禁令或制度当前已经生效并继续适用。

- 持有许可：政策/产业：主体当前拥有从事某项受监管活动的有效许可。

- 具备技术能力：科技：组织、设备或系统当前具备特定技术能力。

- 处于研发阶段：科技：技术或产品当前位于特定成熟度或研发阶段。

- 持有资产：金融：主体当前持有证券、现金、债权或其他金融资产。

- 承担债务：金融：主体当前负有特定偿付义务或债务余额。

### CHANGE

**描述：**表达同一对象在某个可识别维度上的状态、数值、能力、身份、阶段、关系或存在情况发生改变，核心关注什么发生了怎样的前后变化。

#### 角色

- subject: 发生状态、数值、能力、身份、阶段、关系或存在变化的对象。

- dimension: 变化发生所在的属性轴、状态轴或关系轴，用于限定变化究竟发生在哪个方面。

- from: 变化发生前在该维度上的状态或值，原文未提供时允许未知。

- to: 变化发生后、正在趋向或预期达到的状态或值，原文未提供时允许未知。

- agent: 直接实施、推动或决定该变化的主体；变化自发发生或施动者未知时留空。

#### 通用跨领域谓词

- 增加：某个可度量维度向更高数值、规模或程度变化。

- 减少：某个可度量维度向更低数值、规模或程度变化。

- 改善：质量、能力、表现或状态向更有利方向变化。

- 恶化：质量、能力、表现或状态向更不利方向变化。

- 启动：活动或系统由未运行状态进入运行状态。

- 暂停：活动或系统由运行状态进入可恢复的暂时停止状态。

- 终止：活动、关系或资格由有效或进行状态进入结束状态。

- 完成：活动或项目由进行状态达到预定完成标准。

- 建立：对象、关系、能力或制度由不存在进入存在状态。

- 失去：主体原有状态、能力、关系、资格或控制不再成立。

- 恢复：对象由异常、中断或缺失状态回到原有或正常状态。

- 升级：等级、能力、严重性或配置进入更高层级。

- 降级：等级、能力、严重性或配置进入更低层级。

#### 特定领域谓词

- 扩产：产业：企业或工厂的生产能力提高到更高水平。

- 减产：产业：企业或工厂的实际产量或计划产量下降。

- 投产：产业：工厂、产线或设备由建设、调试状态进入生产状态。

- 停产：产业：工厂或产线由生产状态进入暂停或终止状态。

- 提价：产业/市场：产品或服务价格提高。

- 降价：产业/市场：产品或服务价格降低。

- 提高良率：产业：合格产出比例或生产质量改善。

- 任命：组织：人员的职务或制度角色由原状态变为新职务。

- 破产：产业/金融：企业进入法定或事实上的破产状态。

- 夺取：军事：地域、设施或目标的控制方变为行动方。

- 失守：军事：原控制方失去对地域、设施或阵地的控制。

- 动员：军事：人员、装备或组织由常态进入战时准备或集结状态。

- 投降：军事：作战主体由持续抵抗进入停止抵抗并接受对方控制的状态。

- 损毁：军事/产业：设备、设施或对象的完整性和运行状态下降。

- 通信中断：军事/科技：通信链路由连通状态变为断开状态。

- 政策生效：政策：政策或规则由尚未适用进入正式适用状态。

- 撤销许可：政策：许可或资格由有效状态变为无效状态。

- 发现：科技/调查：主体对某项事实由未知或未识别进入已知或识别状态。

- 达到量产条件：科技/产业：技术成熟度进入可稳定规模生产的状态。

- 评级下调：金融：主体或资产的信用评级进入更低等级。

- 发生违约：金融：偿付状态由正常履约进入未按约履行状态。

### TRANSFER

**描述：**表达实体、人员、资源、资金、信息、权利、责任、订单、位置或控制关系从来源端移动、复制、共享、授予或重新归属到目标端，核心关注转移什么、从哪里来和到哪里去。

#### 角色

- theme: 在来源端与目标端之间移动、复制、共享、授予或重新归属的核心对象、资源、信息或关系。

- source: 转移开始前持有、控制、承载、容纳或作为 theme 起点的实体、位置或范围。

- destination: 事件推进或完成后获得、接收、承载或成为 theme 新归属端的实体、位置或范围。

- authority: 决定、批准、命令或有权确认本次转移的主体，其本身通常不承担 theme 的实际移动。

#### 通用跨领域谓词

- 转移：将主题从原来源端移至或重新归属到目标端。

- 移动：实体在空间位置上从起点进入目标位置。

- 交付：提供方将约定对象交给接收方并履行交付事项。

- 供应：来源方向目标方持续或批量提供资源、材料、产品或能力。

- 采购：需求方通过交易从供应方取得产品、材料或服务。

- 出售：原持有方以交易方式将对象或权益转给购买方。

- 收购：取得方通过交易获得企业、业务、资产、权益或控制权。

- 投资：投资方向目标主体转入资金或资源以取得预期权益或回报。

- 分享：信息或资源被复制、开放或共同提供给接收方，来源端通常继续保留。

- 调动：组织将人员、部队、设备或资源从原位置配置到目标位置。

- 撤退：部队、人员或装备离开当前区域并转向后方或其他目标区域。

- 移交：主体将职责、权利、控制、保管或执行责任交给另一主体。

#### 特定领域谓词

- 转让股权：产业/金融：股权从原持有人转移给新持有人。

- 转移控制权：产业：企业、资产或业务的控制关系转入新主体。

- 融资：产业/金融：资金从投资者或贷款方进入融资主体。

- 支付：产业/金融：资金从付款方向收款方转移。

- 出口：产业/政策：商品、技术或服务从境内主体转向境外目标。

- 进口：产业/政策：商品、技术或服务从境外来源进入境内目标。

- 转让技术：产业/科技：技术知识、成果、能力或相关权益转给接收方。

- 授权使用权：产业/科技：特定对象的使用权由权利人授予被许可方。

- 转移订单：产业：采购订单或业务份额从原供应关系转向新供应方。

- 转移产能：产业：生产任务或产能配置从一个设施、地区或主体转向另一个。

- 增援：军事：兵力、装备或资源向需要加强的地区或单位转移。

- 撤离：军事/应急：人员或物资从危险地区转移至安全地区。

- 运送补给：军事：弹药、燃料、食品或装备从后方转向作战单位。

- 移交指挥权：军事：特定行动或单位的指挥权限转交给另一主体。

- 交换俘虏：军事/外交：双方将所控制人员相互移交。

- 分享情报：军事/政策：情报内容被提供给盟友、部门或其他接收者。

- 提供援助：政策/外交：资金、物资、技术或能力转给受援方。

- 发布信息：通用/政策：命题内容由发布者传播给公众或指定受众。

- 发放贷款：金融：贷款资金从资金方向借款人转移。

- 偿还债务：金融：偿付款项从债务人转给债权人。

### APPLY

**描述：**表达行动者对目标实施操作、行为、作用或实际努力，核心关注谁对什么采取了什么行动，行为本身不自动证明预期结果已经实现。

#### 角色

- actor: 主动实施行为、投入努力或控制行动过程的主体。

- target: 行为直接指向、作用、处理、观察或试图实现的对象或目标事件。

- instrument: actor 用于实施行为的工具、系统、资源、方法或主要手段。

- result: 已有明确证据确认并与该行为直接相关的实际结果，仅在结果已经成立时提取。

#### 通用跨领域谓词

- 实施：主体对目标执行一项明确行动或操作。

- 使用：主体将工具、系统、资源或方法用于某项任务或目标。

- 处理：主体对对象进行加工、处置、运算或操作。

- 检查：主体对对象的状态、属性或合规情况进行查验。

- 调查：主体围绕对象、事件或问题收集和核验信息。

- 搜索：主体采取行动寻找人员、对象、位置或信息。

- 测试：主体通过规定方法检验对象的能力、性能或状态。

- 维护：主体对对象采取措施以保持其正常或目标状态。

- 尝试：主体已经投入实际努力以促成目标事件，目标是否实现仍待确认。

- 保护：主体对目标实施防护、监控或风险降低行动。

- 干预：主体介入现有过程并试图改变其运行或结果。

#### 特定领域谓词

- 生产：产业：企业或设施对材料和部件实施制造活动以形成产品。

- 加工：产业：主体对原料、部件或半成品实施工艺处理。

- 研发：产业/科技：主体对技术、产品或工艺开展研究和开发活动。

- 设计：产业/科技：主体形成产品、系统、设备或方案的结构与实现方式。

- 验证：科技：主体通过实验或测试确认技术、模型或系统能否满足目标。

- 安装：产业/科技：主体将设备或系统设置到目标位置并完成配置。

- 维修：产业/科技：主体对故障对象实施修复操作。

- 部署软件：科技：主体将软件安装、配置并置入目标环境。

- 训练模型：科技：主体使用数据和算法对模型参数进行训练。

- 开展尽调：产业/金融：主体对交易目标的经营、资产、风险和合规情况进行调查。

- 攻击：军事：行动方对人员、设施、地域或系统实施敌对行动。

- 空袭：军事：行动方使用航空器或空射武器对目标实施攻击。

- 炮击：军事：行动方使用火炮对目标或区域实施火力打击。

- 拦截：军事：行动方对移动目标实施阻断、接触或摧毁行动。

- 侦察：军事：行动方对地区、目标或部署实施观察和信息收集。

- 巡逻：军事：行动方沿指定地区或路线持续实施警戒和观察。

- 电子干扰：军事/科技：行动方使用电磁手段干扰目标通信、雷达或导航。

- 网络入侵：军事/科技：行动方对信息系统实施未经授权的访问或控制行动。

- 防御：军事：行动方对区域、人员、设施或通道实施防护行动。

- 布雷：军事：行动方在区域或通道布设爆炸性障碍。

- 排雷：军事：行动方对已布雷区域实施探测和清除。

- 举行谈判：政策/外交：参与方围绕议题实施协商活动。

- 开展审计：金融/治理：主体对财务记录、流程或控制实施检查。

- 执行交易：金融：主体对金融工具实施买卖或成交操作。

### MODALIZE

**描述：**表达控制者改变主体实施某项行为的许可、义务、承诺、限制或可行空间，核心关注谁使谁对什么行为变得可以、必须、受限或不得执行。

#### 角色

- controller: 施加、改变或确认许可、义务、限制、承诺或禁止状态的主体。

- subject: 其行为选择、义务或可行空间受到影响的实际承担者。

- action: 受到允许、要求、限制、禁止、承诺、拒绝或豁免的目标行为。

- scope: 模态约束适用的对象、产品、地域、时间、条件、管辖范围或例外范围。

#### 通用跨领域谓词

- 允许：控制者使主体实施目标行为获得许可。

- 要求：控制者使主体承担实施目标行为的义务。

- 批准：有权主体确认特定计划、交易或行为可以继续。

- 授权：控制者赋予主体实施目标行为所需的权限。

- 限制：控制者缩小主体实施目标行为的范围、条件、规模或能力。

- 禁止：控制者使主体不得实施目标行为。

- 承诺：主体主动使自身对未来目标行为承担明确义务。

- 拒绝：主体不接受被请求、提议或要求的目标行为。

- 豁免：控制者解除特定主体原本适用的义务或限制。

- 撤回授权：控制者取消此前授予主体的许可或权限。

- 附加条件：控制者使目标行为仅在满足规定条件时可以继续。

#### 特定领域谓词

- 批准收购：产业/政策：监管或权力主体允许特定收购交易继续推进。

- 有条件批准交易：产业/政策：交易在满足指定条件后获得继续许可。

- 禁止交易：产业/政策：主管主体禁止相关方实施特定交易。

- 出口管制：产业/政策：主管主体限制或禁止特定商品、技术或服务出口。

- 进口限制：产业/政策：主管主体限制特定对象进入目标市场。

- 授予经营许可：产业/政策：主管机构允许主体从事受监管经营活动。

- 要求整改：产业/政策：主管主体要求责任方采取纠正措施。

- 要求召回：产业/政策：主管主体要求企业回收或停止提供相关产品。

- 冻结资产处置：政策/金融：主管主体禁止或限制相关方转移、交易或处置资产。

- 限制市场准入：政策/产业：主管主体限制企业、产品或服务进入特定市场。

- 承诺交付：产业：供应方对未来产品、数量和期限承担交付义务。

- 拒绝出售：产业：权利主体拒绝接受资产或业务出售安排。

- 下令进攻：军事：指挥主体要求部队执行进攻行动。

- 下令撤退：军事：指挥主体要求部队执行撤退行动。

- 授权使用武力：军事：有权主体允许行动方使用规定范围的武力。

- 禁止开火：军事：指挥主体禁止部队实施交战行为。

- 要求停火：军事/外交：一方要求相关行动主体停止交战。

- 设立禁飞区：军事/政策：控制主体禁止指定航空器在规定区域飞行。

- 限制武器使用：军事：指挥或政策主体限定武器使用范围和条件。

- 授予技术许可：科技/产业：权利主体允许被许可方使用受保护技术。

- 限制数据访问：科技/政策：控制主体限定用户、系统或地区访问数据的能力。

- 批准上市：金融：主管主体允许证券或产品进入公开市场。

- 暂停交易：金融：主管主体在规定期间禁止证券继续交易。

- 限制资本流动：金融/政策：主管主体限制资金跨主体、账户或国境转移。

### ATTITUDE

**描述：**表达个人、组织或系统对事件、命题、对象或可能情况持有判断、信念、预测、意图、计划、怀疑、担忧或评价，核心关注谁对什么持有什么认知或意向。

#### 角色

- holder: 持有判断、信念、预测、意图、计划、怀疑、担忧或评价的个人、组织或系统。

- content: 被判断、相信、预测、计划、怀疑、担忧或评价的事件、命题、对象或可能情况。

- basis: 形成该态度所依据的信息、证据、模型、观察、经验或假设，仅在其具有决定性价值时提取。

- confidence: holder 对 content 所持态度的明确程度或确信水平，仅在原文给出可判断表达时提取。

#### 通用跨领域谓词

- 认为：主体接受或倾向接受某项判断或命题。

- 预计：主体判断某个未来事件或状态可能发生。

- 计划：主体已经将未来事件作为拟执行事项进行安排。

- 意图：主体希望或决定促成某个未来事件。

- 考虑：主体正在评估某项可能行动且尚未形成明确决定。

- 怀疑：主体对命题真实性、对象状态或行为动机持不确定或否定倾向。

- 担忧：主体认为某个负面事件可能发生并表达关切。

- 评估：主体对对象、事件、能力、风险或价值形成分析判断。

- 否认：主体明确拒绝接受某项主张为真实。

- 相信：主体将某项命题视为真实或高度可信。

- 预期：主体对未来状态、结果或趋势形成方向性判断。

#### 特定领域谓词

- 计划扩产：产业：企业将提高生产能力作为未来拟执行事项。

- 预计需求变化：产业：企业或机构判断未来市场需求将上升或下降。

- 考虑出售业务：产业：企业正在评估出售业务且尚未作出明确决定。

- 担忧供应短缺：产业：主体认为关键投入可能出现不足。

- 评估收购目标：产业/金融：主体对潜在交易目标的价值、风险和适配性形成判断。

- 下调业绩预期：产业/金融：主体对未来经营或财务表现形成更低判断。

- 计划军事行动：军事：指挥或政治主体将特定军事行动作为未来拟执行事项。

- 判断敌方意图：军事：主体对对方可能采取的行动形成判断。

- 评估威胁：军事：主体对目标的能力、意图和潜在危害形成判断。

- 怀疑欺骗行动：军事：主体认为对方情报或行动可能具有欺骗性。

- 担忧补给中断：军事：主体认为后勤供应可能遭受中断。

- 预测冲突升级：军事/政策：主体判断冲突规模或强度可能提高。

- 计划修订政策：政策：主管主体将调整政策作为未来拟执行事项。

- 判断对方履约：外交/政策：主体对另一方遵守协议的可能性形成判断。

- 预测技术路线：科技：主体判断未来技术方向、成熟时间或性能趋势。

- 认为假设成立：科技：研究主体接受某项假设为合理或得到支持。

- 评估技术可行性：科技：主体对技术能否实现目标形成判断。

- 预计价格变化：金融：主体判断资产或商品价格未来将发生变化。

- 认为资产低估：金融：主体判断资产当前价值低于其合理价值。

- 担忧信用风险：金融：主体认为债务人或资产可能发生信用损失。

### CAUSE

**描述：**表达一个因素、状态或事件对另一个事件产生导致、触发、促进、阻止、延缓、加剧或缓解作用，核心关注原因、结果和作用方向。

#### 角色

- cause: 对结果产生作用的因素、状态或事件，应有文本依据支持其具有因果意义。

- effect: 在因果作用下发生、未发生、改变概率、改变时间或改变程度的结果事件或状态。

- mechanism: 原因作用于结果的主要路径或中间机制，仅在原文明确或对理解核心事件具有决定性价值时提取。

- strength: 原文明确表达的因果确定程度、直接程度或作用强度。

#### 通用跨领域谓词

- 导致：原因使结果发生或形成。

- 触发：原因启动结果事件、过程或状态变化。

- 促进：原因提高结果发生的可能性、速度、规模或程度。

- 阻止：原因使目标结果未能发生或继续。

- 延缓：原因使结果发生或完成的时间推迟。

- 加剧：原因使既有负面状态、风险或影响程度提高。

- 缓解：原因使既有负面状态、风险或影响程度降低。

- 支撑：信息、证据或条件提高某项判断、行动或结果成立的基础。

- 削弱：原因降低对象的能力、状态、概率或影响。

- 迫使：强约束因素使主体采取原本可能不会选择的行动。

#### 特定领域谓词

- 短缺导致停产：产业：关键投入不足使生产活动暂停或终止。

- 供应下降推高价格：产业/市场：可用供给减少使价格上升。

- 成本上升压低利润：产业/金融：投入成本提高使盈利能力下降。

- 扩产缓解短缺：产业：新增产能使供给不足程度下降。

- 技术突破促进需求：产业/科技：技术进步提高产品采用或市场需求。

- 设备故障延缓交付：产业：设备异常使生产或交付时间推迟。

- 需求下降导致库存增加：产业：销售或消耗减少使库存积累。

- 战争扰乱供应链：军事/产业：冲突行动使生产、运输或供应关系受阻。

- 袭击导致损毁：军事：攻击行动使人员、装备或设施受损。

- 损毁导致停运：军事/产业：设施或设备受损使运行活动停止。

- 补给不足迫使撤退：军事：后勤条件不足使部队采取撤退行动。

- 拦截阻止命中：军事：拦截行动使来袭目标未能到达预定目标。

- 增援提升防御能力：军事：新增兵力或装备提高目标地区防御能力。

- 天气延缓行动：军事/运输：天气条件使行动启动或完成时间推迟。

- 通信中断加剧混乱：军事：通信能力丧失使组织和指挥失序程度提高。

- 政策导致投资减少：政策/产业：政策约束或激励变化使投资规模下降。

- 谈判促成协议：外交：协商过程提高并最终促成协议形成。

- 管制阻止出口：政策/产业：规范性限制使出口行为未能实施。

- 缺陷导致系统故障：科技：设计、软件或硬件缺陷使系统异常。

- 修复缓解故障：科技：修复措施降低故障程度或恢复功能。

- 加息导致估值下降：金融：利率上升通过折现或融资成本使资产估值下降。

- 流动性不足触发抛售：金融：可用资金不足使市场主体集中出售资产。

## 6. stage 生命周期阶段

stage 与 FRAME 正交，表示统一谓语所代表事件的生命周期进展。它是事件状态，不承担信息可信度、来源质量或事件重要性的表达。

| **stage**   | **定义**                                                       |
| ----------- | -------------------------------------------------------------- |
| considering | 主体正在考虑该事件，尚未形成明确计划或执行决定。               |
| planned     | 主体已经形成计划、意向或正式方案，事件尚未进入实际执行。       |
| approved    | 事件已经获得必要授权或批准，实际执行尚未开始。                 |
| ordered     | 有权主体已经向实际执行者下达明确要求或命令，执行尚未得到确认。 |
| ongoing     | 事件已经开始并正在执行，目标尚未确认完成。                     |
| suspended   | 事件已经开始，当前暂时中止，后续仍可能恢复。                   |
| completed   | 事件已经达到其目标状态或约定完成标准。                         |
| cancelled   | 事件在完成前被发起方或相关主体主动取消。                       |
| blocked     | 事件因外部决定、审批否决、资源条件或其他障碍无法继续。         |
| failed      | 事件已经尝试或执行，但未达到目标。                             |
| unknown     | 现有材料不足以判断事件当前阶段。                               |
| unavailable | 这类事件无阶段可言。                                           |

## 7. 事件记录结构

每条记录只表达一项核心事件。人物、组织和地点由实体表确定类型，时间由字段名称确定语义，事件记录中不重复保存 type。第一版结构如下：

```
FRAME: TRANSFER

predicate: 收购

specific: null

stage: planned

roles:

  theme: 公司B控股权

  destination: 公司A

  authority: 监管机构

time:

  expected_time: 2026年底

context:

  event_location: 上海

fields:

  amount: 20亿元

  approval_status: pending
```

## 8. 谓词与扩展信息

谓词与扩展信息由谓词注册表定义。本规范只要求 predicate 能够稳定标识事件身份，并允许具体谓词声明角色约束、扩展字段及其他元数据；不限定谓词元数据的内部组成、层级或实现方式。

## 9. TIME 独立块

time 是与 FRAME、predicate、stage、roles、context 和 fields 同级的独立字段块。它只记录核心事件的时序位置，并严格区分事件发生、开始、结束、生效、期限、预期和观察时间。time 不承担事件阶段表达，stage 也不承担时间表达。

| **字段**       | **定义**                                                                                                    |
| -------------- | ----------------------------------------------------------------------------------------------------------- |
| event_time     | 核心事件发生或所描述状态成立的时间，适用于无需区分起止节点的事件。                                          |
| start_time     | 核心事件开始实施、过程开始运行或状态开始成立的时间。                                                        |
| end_time       | 核心事件完成、终止或状态结束的时间。                                                                        |
| effective_time | 政策、许可、协议、禁令、规则或权利义务开始产生效力的时间。                                                  |
| deadline       | 事件必须完成、行为必须执行或条件必须满足的最迟时间。                                                        |
| expected_time  | 尚未实际发生的事件预计开始、发生或完成的时间；需要时可由谓词声明 expected_start_time 或 expected_end_time。 |
| observed_at    | 当前材料观察、确认、报道或提取到该事件阶段的时间，用于区分事件时间与信息获得时间。                          |

时间字段只在原文或可靠元数据提供依据时填写。相对时间应尽可能结合文档发布时间解析为绝对时间，同时保留原始表达以便审计；无法可靠解析时保留原始时间短语。announcement_time 不作为第一版全局字段。宣布本身为核心事件时可使用 event_time；宣布只是传播外壳时，可以忽略或保存在来源元数据中。

## 10. CONTEXT 与地点表达

context 与 time 分开设置。第一版 context 保持极小，只承载不参与核心角色结构的发生环境。地点不单独形成 location 块。地点决定事件对象、来源、目标、关系另一端或行动目标时，直接进入对应 FRAME 的 roles；地点只说明事件发生在哪里，且移除后不改变核心语义时，进入 context.event_location。

- “第X旅从A地区撤退至B地区”中的 A 地区和 B 地区决定转移方向，分别放入 roles.source 和 roles.destination。

- “公司A在上海宣布收购公司B”以收购为核心事件时，上海不改变收购关系，可放入 context.event_location；若只是新闻发布地点且价值很低，可以省略。

- B地区可以在撤退事件中承担 destination，在攻击事件中承担 target，在谈判事件中承担 event_location。实体类型由实体表提供，事件记录只保存语义位置。

## 11. 决定性信息与关键门槛

确定核心谓语后，还应识别会显著改变读者判断的信息。判断标准是：删除该信息后，读者是否会误判事件已经发生、已经完成、能够继续或具有不同规模。若会，应将其保存到 stage、关键门槛、time、金额、数量、地点或结果等可计算字段。

例如：“公司A周三宣布，将以20亿元收购公司B的控股权，交易仍需获得监管机构批准。”核心谓语为“收购”，FRAME 为 TRANSFER。当前已经形成明确交易安排但尚未通过审批，stage 为 planned，approval_status 为 pending，监管机构进入 authority，金额 20 亿元进入 amount。监管批准后，stage 更新为 approved；完成交割后更新为 completed；监管否决后更新为 blocked。

## 12. 事件连续性与阶段历史

系统串联不同情报时，应比较统一谓语、实际执行主体、核心对象、来源地、目标地和大致时间窗口。匹配到同一个现实事件后，保持 FRAME、predicate 和关键角色稳定，通过 stage 与 time 记录进展。

“要求第X旅撤退至B地区”“第X旅正在撤退至B地区”“第X旅已经撤退至B地区”应归入同一撤退事件，FRAME 均为 TRANSFER，predicate 均为“撤退”，stage 依次为 ordered、ongoing 和 completed。下令者记录为 authority 或阶段来源，实际执行者持续作为 theme。

每次观察应保留时间和来源。后续可靠材料推翻早期报道时，应更新当前判断并保留被纠正的旧观察。

## 13. 边界与消歧规则

三份原始文档不存在必须由外部决策才能解决的直接冲突，但有三组容易混淆的边界。整合时保留两种表达能力，并以文章焦点和持续跟踪对象作为选择依据。

**底层事件与审批、命令：**文章持续跟踪收购、撤退等底层事件时，批准、要求和下令用于 stage、authority 或关键门槛；文章核心就是监管决定或命令本身时，可以单独记录为 MODALIZE，例如“批准收购”或“下令撤退”。

**事件谓语与阶段词：**启动、暂停、完成、终止既可作为 CHANGE 谓语，也可表现其他事件的 stage。文章跟踪某项既有事件的进展时使用 stage；文章核心是对象从运行到停止、从未建成到完成等状态变化时使用 CHANGE 谓语。

**态度谓语与未来阶段：**计划、考虑既可作为 ATTITUDE 谓语，也可表现底层事件的 considering 或 planned。能够确定底层事件身份且系统需要持续串联其执行进展时，保留底层 predicate 并使用 stage；文章核心只表达主体的认知、意向或评估，或底层事件尚无法稳定识别时，使用 ATTITUDE。

## 14. 核心结构验收规则

- 核心事件记录应具有唯一 FRAME、稳定 predicate、与 FRAME 相符的核心角色和明确 stage，不得混入多个核心事件。

## 附录 A. FRAME 与谓词元数据中的文本模板

文本模板属于 FRAME 和 predicate 的元数据，不属于核心事件记录。具体谓词可以在元数据中定义模板；具体谓词未定义模板时，生成器回退到所属 FRAME 的模板。模板只负责将已有结构生成标准文本，不改变事件语义，也不得补充结构中不存在的事实。

| **模板组成**   | **职责**                                                                                     |
| -------------- | -------------------------------------------------------------------------------------------- |
| FRAME 回退模板 | 提供最低限度的结构化表达，例如 TRANSFER 可回退为“{theme} 从 {source} 转移至 {destination}”。 |
| 谓词核心模板   | 决定句子主语、谓语实现、角色顺序和必要介词。                                                 |
| 谓词可选短语   | 将金额、来源、工具、门槛、时间和结果等字段按固定位置加入句子。                               |
| stage 表达     | 将 planned、ordered、ongoing、completed 等阶段转换为适合谓词的自然语言。                     |
| 自定义字段表述 | 临时字段必须提供 kind 和 surface，生成器按类型确定位置并直接使用 surface。                   |

核心句式只引用构成事件身份所需的字段；可选短语仅在对应字段存在时加入；字段缺失时删除整个相关短语，禁止生成空介词、占位符或根据常识补全内容。

### 收购模板示例

predicate: 收购

frame: TRANSFER

core_template: "{destination}{stage_phrase}{amount_phrase}收购{theme}"

optional_phrases:

amount: "以{amount}"

approval_pending: "，交易尚待{authority}批准"

approval_approved: "，交易已获{authority}批准"

expected_time: "，预计于{expected_time}完成"

stage_realization:

considering: "正在考虑"

planned: "拟"

approved: "已获批准，将"

ongoing: "正在推进"

completed: "已完成"

blocked: "收购受阻，拟"

当 destination 为公司A、theme 为公司B控股权、stage 为 planned、amount 为20亿元、authority 为监管机构且 approval_status 为 pending 时，生成：“公司A拟以20亿元收购公司B控股权，交易尚待监管机构批准。”

### 撤退模板示例

predicate: 撤退

frame: TRANSFER

core_template: "{theme}{stage_phrase}{deadline_phrase}{source_phrase}撤退至{destination}"

optional_phrases:

source: "从{source}"

deadline: "在{deadline}内"

authority_ordered: "奉{authority}命令"

stage_realization:

planned: "计划"

ordered: "奉命"

ongoing: "正在"

suspended: "暂停"

completed: "已经"

failed: "未能完成"

当 theme 为第X旅、source 为A地区、destination 为B地区、stage 为 ordered、authority 为指挥部且 deadline 为24小时时，生成：“第X旅奉命在24小时内从A地区撤退至B地区。”
